## 1. 핵심 원칙

1. **라벨이 기준이고, CoT는 안내 자료다.** 최종 판정은 라벨로 하고, CoT는 추론 형식과 판정 기준의 방향을 잡는 데 쓴다.
2. **pass@8은 목표가 아니다.** 분류 문제에서 pass@k는 크게 부풀려진다. 현실적인 기준선은 MV@k다 (2절).
3. **Stage 1(SFT)의 목표는 "정확도 최대"가 아니라 "RL을 시작하기 좋은 상태"다.** 형식 안정, 떨어진 구간 없음, 다양성 유지가 기준이다.
4. **zero-shot이 강하면 SFT는 가볍게 하거나 생략한다.** off-policy trace로 SFT하면 오히려 성능이 떨어질 수 있다.
5. **가장 싸고 정보가 많은 실험은 "라벨 검수 + 소규모 GRPO pilot"이다.** SFT·DPO·on-policy distillation은 pilot에서 문제가 확인된 뒤에 꺼낼 카드다.
6. **반드시 "추론 없이 답만 내도록 학습한 모델"과 비교한다.** 분류 문제에서 CoT가 항상 이기지는 않는다.

## 2. 분류 문제에서 pass@k 읽는 법

### pass@k가 부풀려지는 이유
- 라벨이 몇 개뿐이라, 확신 없는 샘플도 8번 생성하면 정답 라벨이 한 번쯤 나온다.
- 서빙 시에는 8개 답 중 무엇이 정답인지 골라 줄 verifier가 없다.
- 따라서 학습으로 옮길 수 있는 몫의 기준선은 **MV@k(다수결)** 다. 단, 이것은 **법칙이 아니라 경험적 기준**이다. RL로 학습한 내용이 일반화되면 처음 측정한 MV@k를 넘을 수도 있다.

### 곡선 모양으로 원인 구분하기
샘플 하나를 한 번 생성했을 때 맞힐 확률을 p라고 하면:
```
pass@k = 1 − E[(1−p)^k]
k → k+1 증가분 = E[ p · (1−p)^k ]     # k가 커질수록 줄어듦 → 곡선은 항상 위로 볼록
```
- **p가 중간값(0.3~0.6)인 샘플이 많으면** k=2~3에서 포화하고 곡선이 급하게 꺾인다.
- **p가 작은 샘플(0.1~0.15)이 많으면** 곡선이 거의 직선이 된다.

같은 pass@1 93 / pass@8 98을 만드는 두 시나리오:

| | A: 꺾이는 곡선 | B: 직선에 가까운 곡선 |
|---|---|---|
| 구성 | 88% 항상 맞힘, 10%는 p=0.5, 2% 항상 틀림 | 92% 항상 맞힘, 8%는 p≈0.15 |
| pass@1 → 2 → 4 → 8 | 93 → 95.5 → 97.4 → 98.0 | 93.2 → 94.2 → 95.8 → 97.8 |
| MV@8 | 약 96~97 | **약 92 (pass@1과 비슷하거나 낮음)** |
| 해석 | 다수결로 대부분 회복 가능 → RL로 개선할 여지가 큼 | 대부분 우연히 맞힌 몫 |

### 직선 곡선일 때 의심할 원인
모델이 일관되게 같은 오답을 내는 샘플은 보통 셋 중 하나다.
1. **라벨 노이즈** — 모델의 답이 오히려 맞고 라벨이 틀림
2. **지식 부족** — 브랜드, 시리즈, 카테고리 규칙 등 모델이 모르는 정보가 판정을 좌우함 (K-CARE의 "지식 경계")
3. **모호한 클래스 경계** — 예: Perfect와 Passable

## 3. 지표 정의

모든 지표는 샘플별 정답 확률 p에서 시작한다.

### 3.0 p — 샘플별 정답 확률

**p는 샘플 하나에 대해 모델이 정답을 낼 확률**이다. 샘플마다 따로 정의되므로 엄밀히는 샘플 i의 p_i다.
```
p_i = P( 모델이 샘플 i에 대해 생성한 답 == 정답 라벨 )
```
temperature > 0이면 모델은 같은 입력에도 매번 다른 추론과 답을 생성한다. p는 그중 정답이 나올 확률이다.

**측정 방법**: 실제 확률은 알 수 없으므로 여러 번 생성해 정답 비율로 추정한다.
```
샘플 i를 T=1.0으로 n번(16 이상 권장) 생성
p_i ≈ (정답이 나온 횟수) / n
```

**예시**: query "tf 향수", 상품 "TOM FORD 오드퍼퓸", 정답 라벨 Perfect

| 생성 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 답 | Perfect | Bad | Perfect | Perfect | Passable | Perfect | Bad | Perfect |

→ 8번 중 Perfect 5번이므로 p ≈ 5/8 = 0.625

**다른 지표와의 관계**: p는 샘플 단위 값이고, 나머지 지표는 모두 이것을 데이터셋 전체에서 모은 것이다.

| 지표 | p로 표현 |
|---|---|
| pass@1 | 모든 샘플의 p 평균 |
| pass@k | 1 − 평균[(1−p)^k] |
| learnable_frac | 0 < p < 1인 샘플 비율 |
| zero_adv_frac | 평균[p^G + (1−p)^G] |
| p 히스토그램 | 샘플들의 p 분포 |

### 3.1 RL 준비도 지표

| 지표 | 정의 | 답하는 질문 | 쓰는 시점 |
|---|---|---|---|
| **learnable_frac** | `P(0 < p < 1)` | 학습 신호가 나올 수 있는 데이터가 얼마나 있나? | RL 전, 데이터 풀 선택 |
| **zero_adv_frac** | `E[p^G + (1−p)^G]` (G = group size) | 이 group size에서 rollout 계산이 얼마나 낭비되나? | G 결정, dynamic sampling 판단, 학습 중 포화 감지 |
| **sharpen_gap** | `MV@8 − pass@1` (안정적으로는 MV@∞) | 분포를 날카롭게 만들면 정확도가 얼마나 오르나? | RL을 할지 말지 결정 |
| signal | `E[p(1−p)]` | GRPO gradient의 평균 크기 | 보조 지표 |
| lottery_gap | `pass@16 − MV@8` | 우연히 맞히는 몫 | 기대 이득 추정 |

- **learnable_frac과 zero_adv_frac의 차이**: p=0.9인 샘플은 learnable하지만, G=8에서는 8개 모두 맞힐 확률이 0.9^8 ≈ 43%다. learnable_frac은 데이터의 잠재력을, zero_adv_frac은 실제 학습 설정에서의 효율을 본다.
- **MV@∞**: n=16 이상으로 생성해, 정답이 가장 많이 나온 라벨(mode)인 샘플의 비율로 계산한다.

### 3.2 오답 구조 지표

| 지표 | 정의 | 의미 |
|---|---|---|
| dominant_wrong | 가장 많이 나온 오답 라벨의 비율 | 오답이 한 라벨에 몰렸는지 |
| **confident_wrong** | `P(dominant_wrong ≥ 0.75)` | 같은 오답을 일관되게 냄 → DPO 후보 |
| scattered_wrong | 오답이 여러 라벨로 흩어진 샘플 비율 | 모델이 확신이 없음 → GRPO 후보 |
| confusion_pair | 오답이 몰리는 (정답 → 오답) 클래스 쌍 | 클래스 쌍별 reward나 판정 규칙의 대상 |

### 3.3 분포 이동(off-policy) 지표

#### Off-policy trace란
**지금 학습하는 모델(policy)이 아닌 다른 분포에서 생성된 추론 과정**이다.
```
policy π_θ      : 지금 학습하는 모델
on-policy trace : y ~ π_θ(· | x)                       # 모델 자신이 같은 입력 x로 생성
off-policy trace: y ~ μ(· | x'),  μ ≠ π_θ 또는 x' ≠ x   # 다른 모델, 또는 다른 입력 조건에서 생성
```
on/off는 둘 중 하나로 나뉘는 개념이 아니라 **정도의 문제**다. 학생 모델 입장에서 얼마나 낯선지(NLL, KL)로 잰다.

| trace 출처 | on/off 정도 | 이유 |
|---|---|---|
| 모델 자신이 같은 prompt로 생성 (GRPO rollout) | on-policy | 정의 그대로 |
| 모델 자신이 생성해서 맞힌 것만 골라냄 (RFT) | 거의 on-policy | 골라내는 과정에서 약간 치우치지만 분포는 모델 자신의 것 |
| 이전 checkpoint가 생성 | 약간 off | 학습이 진행되면서 policy가 이동함 |
| **같은 모델에 정답 힌트를 주고 생성 (rationalization)** | **off** | 모델은 같지만 조건이 p(y \| x, label)이라 서빙 때의 p(y \| x)와 다름 |
| 같은 계열의 더 큰 teacher | off | 지식, 문체, 길이가 다름 |
| 다른 계열의 teacher | 크게 off | tokenizer, 문체, 추론 방식이 모두 다름 |
| 사람이 작성한 CoT | 크게 off | LLM이 자연스럽게 생성하는 분포와 전혀 다름 |

**왜 문제가 되나**
1. **학습과 추론의 불일치 (exposure bias)**: SFT는 teacher가 쓴 앞부분을 보고 다음 토큰을 맞히도록 학습하지만, 추론 때는 모델이 직접 생성한 앞부분을 보고 이어 쓴다. 앞부분이 조금만 벗어나도 학습 때 보지 못한 상태가 되고 오류가 누적된다.
2. **따라 할 수 없는 경로 강요**: 학생 모델이 스스로 도달하지 못하는 추론이면 내용 대신 문체, 길이, 정형 문구만 흉내 낸다.
3. **기존 분포 손상**: 낯선 토큰에 확률을 크게 옮기면서 원래 잘 하던 추론 방식의 확률이 떨어진다 (self_NLL_drift 증가).

GRPO, RFT, on-policy distillation은 모두 **학생 모델이 직접 생성한 trace**로 학습하므로 이 문제를 피한다.

#### 측정 지표

| 지표 | 정의 | 의미 |
|---|---|---|
| **rel_NLL** | `NLL_base(SFT trace) − NLL_base(base 자신의 정답 trace)` | SFT trace가 base 모델에게 얼마나 낯선가 (내용 난이도는 상쇄됨) |
| surprise_rate | `P(p_base(token) < 0.01)` | 낯선 토큰이 문체 쪽인지 내용 쪽인지 |
| KL_est | `mean_t [log p_sft(y_t) − log p_base(y_t)]`, y는 SFT 모델이 생성 | SFT로 모델이 얼마나 이동했나 |
| **self_NLL_drift** | `NLL_sft(base 정답 trace) − NLL_base(base 정답 trace)` | base 모델의 원래 추론 방식을 잊었나 |
| teacher 판별기 비율 | teacher/base trace 분류기를 SFT 출력에 적용 | 문체만 흉내 내고 있나 |

### 3.4 추론 품질 지표

| 지표 | 방법 | 이상 신호 |
|---|---|---|
| **Think 제거 실험** | think 없이 답만 생성해 정확도 비교 | 차이가 없음 → 추론이 장식임 |
| Think 오염 실험 | think 중간에 틀린 사실 삽입 / 일부 잘라냄 | 답이 바뀌지 않음 → 답이 추론을 따르지 않음 |
| 추론↔답 일치율 | judge가 "이 think에서 이 답이 도출되는가" 판정 | 불일치율 증가 |
| 근거 없는 정답 비율 | verifier로 정답 trace의 근거 검사 | 높으면 결과 reward만으로 RL하면 위험 |

## 4. CoT 데이터와 라벨 데이터 사용법

### 4.1 CoT 데이터 점검
```
1. CoT 결론 == 라벨 ?       → 일치율 측정
2. 불일치 샘플               → 라벨 오류인지 CoT 오류인지 판정 (다중 LLM arbitration 또는 사람)
3. CoT 출처 (teacher? 사람?) → 학습할 모델 기준 rel_NLL로 off-policy 정도 측정
4. CoT 품질                  → 결론만 맞고 근거가 틀린 trace를 verifier로 제거
```

### 4.2 데이터별 사용처

| 데이터          | 상태                       | 사용처                                                   |
| ------------ | ------------------------ | ----------------------------------------------------- |
| CoT + 라벨     | 결론 일치, 품질 통과, rel_NLL 낮음 | **Stage 1 SFT**                                       |
| CoT + 라벨     | 결론 일치, rel_NLL 높음        | 학생 모델이 자기 문체로 재작성 후 SFT, 또는 DPO chosen                |
| CoT + 라벨     | 결론 불일치                   | arbitration 후 수정하거나 제외                                |
| **라벨만 (대량)** | —                        | **Stage 3 GRPO의 prompt와 reward**, Stage 2 RFT의 원천 데이터 |


### 4.3 역할 분담
```
CoT 데이터  → 추론 형식과 판정 기준 학습 (적은 양, 고품질, cold start용)
라벨 데이터 → RL 보상, 자기 trace 생성, 평가 (많은 양, 더 중요한 자산)
```
- RL에서는 정답만 있으면 모델이 스스로 추론 경로를 찾으므로 CoT가 필요 없다. 오히려 on-policy라서 분포 이동 문제가 없다.
- zero-shot이 이미 강하면 CoT 데이터는 적게 쓰거나, **p=0 샘플의 guidance**로 아껴 둔다.
- SFT 데이터의 결론은 반드시 라벨과 일치시킨다. 결론과 라벨이 다른 샘플을 넣으면 추론과 답이 따로 노는 상태를 학습한다.

## 6. Stage 0 — Baseline과 데이터 점검

**목적**: 출발점을 확인하고, 데이터 문제를 미리 찾는다.

### 측정

| 측정 | 방법 | 판단 |
|---|---|---|
| zero-shot pass@1 (think 켬/끔) | 서빙 설정 | think가 몇 pt를 기여하는지 |
| **답만 내는 SFT 대조군** | 추론 없이 라벨로 SFT | 추론 모델이 넘어야 할 기준선 |
| p 히스토그램, MV@8, pass@k 곡선 | n=16 | 곡선 모양, sharpen_gap |
| 샘플 그룹 비율 | 항상 맞힘(8/8) / 섞임(1~7/8) / 항상 틀림(0/8) | 섞임 그룹 = RL로 개선할 수 있는 영역 |
| **라벨 노이즈율** | p ≤ 0.125 샘플 100건 검수 | 20%를 넘으면 정제부터 |
| CoT↔라벨 결론 일치율 | CoT 데이터 전체 | 불일치는 arbitration |
| CoT의 rel_NLL 분포 | base 모델로 NLL 계산 | 상위 꼬리가 길면 off-policy 위험 |
| 예측 클래스 분포 vs 정답 분포 | — | prior가 쏠려 있는지 |

**다음 단계 조건**: 라벨 노이즈가 처리되었고 SFT 데이터가 확정되었을 때.

## 7. Stage 1 — SFT

**목적**: 형식과 판정 기준을 배우되 기존 능력을 잃지 않는 것.

### 7.1 SFT 강도

SFT를 얼마나 할지는 zero-shot 모델이 **무엇을 이미 할 수 있고 무엇을 못 하는지**로 정한다. 정확도 하나로 정하지 않는다.

#### 7.1.1 측정 전 준비: 프롬프트부터 고정
zero-shot 수준은 프롬프트에 크게 좌우된다. 프롬프트가 부실한 상태에서 측정하면 SFT가 해결할 문제와 프롬프트로 해결될 문제를 구분할 수 없다.
- **라벨 정의를 프롬프트에 명시**: 각 클래스의 판정 기준과 경계 사례 규칙 (예: "같은 브랜드라도 시리즈명이 다르면 Bad")
- **출력 형식을 명시**: think 태그, 답 위치, 허용 라벨 목록
- **프롬프트 변형 2~3개를 Dev에서 비교**해 가장 좋은 것을 고정한다. 이후 SFT·RL도 같은 프롬프트를 쓴다.

#### 7.1.2 측정 항목 (Dev, 고정 프롬프트)

| #   | 측정            | 방법                                                             | 무엇을 알려 주나                                               |
| --- | ------------- | -------------------------------------------------------------- | ------------------------------------------------------- |
| ①   | **형식 안정성**    | 파싱 실패율, think 잘림률, 허용 라벨 외 출력 비율                               | 형식을 배워야 하는가                                             |
| ②   | **정확도**       | pass@1 (서빙 디코딩), Macro F1, 클래스별 P/R                            | 전반적 수준                                                  |
| ③   | **대조군 대비 위치** | 같은 학습 데이터로 **추론 없이 답만 내도록 SFT한 모델**의 성능과 비교                    | 절대 점수가 아니라 "학습하면 도달 가능한 수준" 대비 얼마나 부족한가                 |
| ④   | **판정 기준 정렬**  | confusion matrix에서 오류가 **인접 클래스 쌍**(예: Perfect↔Passable)에 몰리는지 | 모델이 라벨 기준을 사람과 다르게 이해하는가                                |
| ⑤   | **Prior 편향**  | 예측 클래스 분포 vs 정답 분포                                             | 특정 클래스로 쏠리는가 (예: zero-shot LLM의 낙관 편향 — Bad recall이 낮음) |
| ⑥   | **추론 기여**     | think 켬 vs 끔 정확도 차이                                            | think가 실제로 도움이 되는가                                      |
| ⑦   | **안정성**       | p 히스토그램, MV@8 − pass@1                                         | 이미 아는 것을 일관되게 못 하는가 (sharpening 대상)                     |


#### 7.1.3 판정 → SFT 강도

| 프로파일 | 진단 | SFT 전략 |
|---|---|---|
| ① 형식 오류 > 1% | 형식 미숙 | **형식 SFT** — 소량(수천 건), 자기 trace 위주로 형식만 학습 |
| ③ 답만 내는 SFT 대조군보다 크게 낮음 (예: 5pt 이상) | 과제 자체를 잘 모름 | **CoT SFT를 충분히** — 7.2절 설정으로 본격 학습 |
| ④ 인접 클래스 쌍 오류 집중 | 판정 기준 불일치 | 먼저 프롬프트에 기준 보강 → 남으면 **해당 클래스 쌍 중심 SFT** (경계 사례 + 기준을 설명하는 trace) 또는 DPO |
| ⑤ prior 편향 큼 | 편향 | 클래스 균형을 맞춘 SFT, 또는 RL에서 클래스별 reward 가중 |
| ⑥ think 기여 ≈ 0 | 추론이 장식 | CoT SFT 전에 **답만 내는 모델이 더 나은지** 먼저 판단. 추론이 필요 없을 수도 있음 |
| ⑦ MV@8 − pass@1 큼, 나머지 양호 | 알지만 일관성 부족 | **SFT 생략 → GRPO** |
| ⑧ 프롬프트 민감도 큼 | 판단이 불안정 | 가벼운 SFT로 기준을 고정 (형식 + 기준 정렬) |
| ①~⑥ 모두 양호, ③ 대조군과 비슷하거나 높음 | 이미 강함 | **SFT 생략 또는 형식만** → 바로 GRPO |

#### 7.1.4 요약 기준

| zero-shot 수준 | 기준 (예시) | 전략 |
|---|---|---|
| **약함** | 형식 오류 > 1%, 또는 답만 내는 대조군보다 5pt 이상 낮음 | CoT SFT를 충분히 |
| **중간** | 형식은 안정, 대조군보다 1~5pt 낮음, 또는 인접 클래스 오류 집중 | 기준 정렬 위주의 가벼운 SFT (경계 사례 중심) |
| **강함** | 형식 안정, 대조군과 비슷하거나 높음, 편향 없음 | **SFT 생략 또는 형식만** → GRPO |


### 7.2 학습 설정
- 클래스 비율은 원래 분포를 유지하고, 쉬운 샘플 replay를 50% 이상 둔다.
- **자기 자신이 생성해서 맞힌 trace를 우선 사용**한다 (on-policy, 가장 안전).
- teacher trace는 학생 모델이 자기 문체로 다시 쓰게 하고, 결론이 맞은 것만 남긴다.
- 샘플당 서로 다른 정답 trace 2~4개를 넣어 다양성을 유지한다.
- LoRA, 낮은 learning rate, 1~2 epoch. loss는 response 토큰에만 걸고 think 템플릿을 정확히 맞춘다.
- 일정 step마다 held-out pass@1을 측정해 early stopping한다.

```
for (q, i, label) in hard_set:                     # 정답 0~3/8 샘플
    traces = Model(q, i, features)                 # 1순위: 자기 생성 정답 trace
             or Teacher(q, i, features)            # 2순위: teacher → 학생이 재작성
    judge  = Verifier(trace)                       # 결론뿐 아니라 근거도 검증
    keep 2~4개의 서로 다른 타당한 trace
SFT(easy 일부 + medium + hard(오버샘플링))
```

### 7.3 측정

**학습 중 (일정 step마다)**

| 측정 | 이상 신호 | 대처 |
|---|---|---|
| train / held-out loss | held-out loss 상승 | early stopping |
| 구간별 held-out pass@1 | **쉬운 구간 하락** | learning rate ↓, 자기 trace replay ↑ |
| base 대비 KL | 급증 | 학습 강도 ↓ |

**학습 후**

| 측정 | 통과 기준 |
|---|---|
| pass@1 (전체 / 구간별) | zero-shot 이상, 하락한 구간 없음 |
| 형식 오류율, think 잘림률 | 1% 미만 |
| pass@8, 샘플당 서로 다른 답의 수 | 크게 떨어지지 않음 |
| Think 제거 실험 | think가 있을 때 유의하게 높음 |
| 추론↔답 일치율 | 높게 유지 |
| self_NLL_drift | 작음 |
| teacher 판별기 비율 | 문체만 흉내 내지 않음 |
| 클래스별 recall, 예측 prior | 원래 분포 유지 |

### 7.4 언제 다음 단계로 넘어가나

**필수 조건 (모두 통과)**

| 조건 | 기준 |
|---|---|
| 형식 안정 | 파싱 실패율, think 잘림률 1% 미만 |
| 하락한 구간 없음 | 모든 구간 pass@1 ≥ zero-shot (통계 오차 범위 안이면 허용) |
| 다양성 유지 | pass@8, 서로 다른 답의 수가 크게 떨어지지 않음 |
| 추론이 실제로 기여 | think를 지우면 정확도가 떨어짐 |
| prior 유지 | 예측 클래스 분포가 정답 분포에서 크게 벗어나지 않음 |

**RL 준비도 (높을수록 좋음)**: sharpen_gap ≥ 1pt, zero_adv_frac < 60%, learnable_frac 충분

**멈출 시점**: held-out pass@1이 정체되는데 pass@8이나 entropy가 떨어지기 시작하면 멈춘다. **정확도가 가장 높은 지점보다 약간 이른 checkpoint**가 RL 출발점으로 더 나은 경우가 많다.

**예외**: pass@1이 zero-shot보다 약간 낮더라도 **MV@8이 오르고, 형식이 안정되고, 쉬운 구간 하락이 없으면** 넘어가도 된다. RL은 MV@k 쪽 잠재력을 pass@1로 끌어오기 때문이다.

### 7.5 SFT 후 zero-shot보다 떨어지면

**Step A — 진짜 하락인지 확인**

| 확인 항목 | 흔한 원인 |
|---|---|
| 파싱 실패율 | 답 형식이 바뀌어 파서가 못 읽음 → 오답으로 집계 |
| 채팅 템플릿, think 태그 | 학습 템플릿과 평가 템플릿이 다름 |
| 디코딩 설정 | temperature, max_len이 다름 |
| think 잘림 | SFT 후 think가 길어져 max_len 초과 |
| 통계 오차 | 노이즈 범위 안 |

**Step B — 어디서 떨어졌는지 찾기**
- 구간별 pass@1, 클래스별 recall, confusion matrix
- step별 정확도 곡선: 초반부터 떨어지면 **데이터 문제**, 올랐다가 떨어지면 **과학습**

**Step C — 원인별 대처**

| 증상 | 원인 | 대처 |
|---|---|---|
| 쉬운 구간 하락 | forgetting | learning rate ↓, LoRA, step ↓, 자기 trace replay, 이른 checkpoint |
| 특정 클래스 recall만 오름 | 라벨 prior 이동 | 클래스 비율 rebalance |
| 어려운 구간 하락, 확신 있는 오답 증가 | 품질 낮은 trace (rationalization, 근거 없는 정답) | faithfulness 필터링, 힌트 없이 생성해 맞힌 trace만 |
| 전 구간 고르게 하락 + 문체 변화 | off-policy trace | rel_NLL 필터링, 학생 모델이 재작성 |
| held-out에서만 하락 | SFT 데이터의 라벨 노이즈 | 결론↔라벨 불일치 샘플 재판정 |
| 올랐다가 하락 | 과학습 | early stopping |

### 7.6 Off-policy 원인 확인 실험
```
SFT 데이터를 rel_NLL 기준 3분위로 나눔 (같은 크기, 같은 클래스 비율)
  Run L: 하위 1/3 (on-policy에 가까움)
  Run H: 상위 1/3 (off-policy)
  Run S: base 모델 자신의 정답 trace만 (기준선)
→ 구간별 pass@1, pass@8, KL_est, self_NLL_drift, 판별기 비율 비교
```
Run H에서만 하락이 나타나면 off-policy가 원인으로 확정된다.

| 측정 결과 | 대처 |
|---|---|
| rel_NLL 상위 꼬리가 하락을 주도 | rel_NLL threshold로 필터링 |
| 문체 토큰 surprise 높음, 판별기 비율 높음 | 학생 모델이 자기 문체로 재작성 |
| faithfulness 낮음 | rationalization trace 제거 |
| self_NLL_drift 큼, 쉬운 구간 하락 | 자기 trace replay ↑, learning rate ↓, LoRA |
| 필터링 후 남는 데이터가 너무 적음 | on-policy distillation 또는 guided GRPO |

### 7.7 Off-policy 완화 조치
효과 대비 비용이 좋은 순서로 정리한다.

**① 데이터를 on-policy에 가깝게 만들기 (가장 효과가 큼)**

| 조치 | 방법 | 비고 |
|---|---|---|
| **자기 trace 우선 (RFT / STaR)** | 학생이 힌트 없이 n=16~32개 생성 → 정답만 채택 | 가장 안전. 어려운 샘플은 n을 늘려 확보 |
| **학생이 teacher trace를 재작성** | teacher trace를 참고로 주고 학생이 자기 말로 다시 씀 → 결론이 맞은 것만 채택 | 내용은 teacher 것, 문체는 학생 분포 |
| **최소 prefix 유도** | teacher trace 앞부분 k 토큰만 주고 학생이 이어 씀. 정답에 도달하는 최소 k를 찾음 | 실마리만 빌림 |
| **teacher 선택** | 같은 계열이거나 tokenizer가 같은 teacher 우선 | 계열이 다를수록 off 정도가 커짐 |
| **형식 정렬** | 학생의 채팅 템플릿·think 태그로 변환, 길이를 학생 분포 범위로 맞춤 | 놓치기 쉽지만 효과가 큼 |

**② 선별**
- **rel_NLL threshold**: 상위 꼬리(예: 상위 20~30%) 제외
- **같은 샘플에 정답 trace가 여러 개면 학생 기준 NLL이 가장 낮은 것 선택**: 같은 정답이라도 학생에게 가장 자연스러운 경로
- **Faithfulness 필터**: verifier로 결론만 맞고 근거가 틀린 trace 제거
- **Rationalization trace 제외**: 학생 재작성과 검증을 거친 경우가 아니면 쓰지 않음

**③ Loss 조정**

| 조치 | 방법 | 효과 |
|---|---|---|
| **샘플 가중치** | `w = exp(−α · rel_NLL)` | 버리지 않고 영향만 줄임 |
| **토큰 단위 clipping** | 학생 확률이 아주 낮은 토큰(예: p < 0.001)의 loss를 상한으로 자르거나 가중치 ↓ | 문체 토큰 하나로 생기는 큰 gradient 방지 |
| **KL anchor** | `L = L_SFT + λ · KL(π_θ ‖ π_base)`, KL은 학생 생성 샘플 또는 base 정답 trace에서 계산 | 원래 분포에서 멀어지는 정도를 직접 제한 |
| **로그 확률 보존** | base 자기 trace를 replay하고 그 NLL이 오르지 않게 모니터링 | self_NLL_drift 억제 |

**④ 학습 설정**
- 데이터 구성: 자기 trace 50% 이상, 클래스 비율 유지, 샘플당 서로 다른 trace 2~4개
- 학습 강도: LoRA, 낮은 learning rate, 1 epoch, held-out 기준 early stopping
- Curriculum: 자기 trace만 → 재작성 trace 추가 → teacher 원문은 마지막에 소량만 (또는 넣지 않음)

**⑤ 측정하며 진행**: rel_NLL, KL_est, self_NLL_drift, 판별기 비율, 구간별 pass@1·pass@8을 계속 보고, 하나라도 나빠지면 직전 설정으로 돌아간다.

**권장 순서**
```
1. 형식 정렬 + 자기 trace RFT              ← 먼저 이것만으로 효과 확인
2. 부족한 어려운 샘플: 학생 재작성 trace 추가
3. 그래도 안 풀리는 샘플: 최소 prefix 유도
4. 남는 teacher trace: rel_NLL 필터 + 샘플 가중치 + KL anchor
5. 그래도 떨어지면: SFT 생략 → GRPO / on-policy distillation
```
> **핵심**: teacher에게서는 **내용(어떤 근거로 판정하는가)만 빌리고**, 문장은 **학생 모델의 분포로** 쓰게 한다.
