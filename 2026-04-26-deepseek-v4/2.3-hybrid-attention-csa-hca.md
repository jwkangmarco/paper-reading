# §2.3 Hybrid Attention with CSA and HCA — 차근차근

V4 의 **단일 dominant contribution**. "1M 토큰 context 를 어떻게 효율적으로 처리할까" 에 대한 V4 의 답이다. attention 비용을 한 자릿수 % 까지 떨어뜨리는 것이 핵심.

---

## 1단계: 출발점 — Vanilla Attention 의 quadratic 병목

표준 attention (Vaswani et al. 2017):

```
Attention(Q,K,V) = softmax(Q K^T / √d) V
```

- 시퀀스 길이 `n` 일 때 **FLOPs ∝ n²**, **KV cache ∝ n** (per layer)
- 1M context: n²= 10^12 → **GPU 한 대로는 비현실적**
- KV cache: layer 당 수 GB, 100+ layer → 수백 GB

→ ultra-long context 의 본질적 병목.

### Attention 비용을 줄이는 두 축

1. **Compression**: KV entries 자체를 작게 만들기 → cache 크기 ↓
2. **Sparsity**: query 가 모든 token 이 아닌 일부만 attend → FLOPs ↓

DeepSeek 시리즈는 두 축을 따로 시도해온 역사가 있다.

---

## 2단계: 전 단계 (1) — MLA (V2/V3): Compression

**Multi-head Latent Attention (MLA)** (DeepSeek-V2, [P10]) — KV cache 압축의 첫 시도:

### 핵심 아이디어
- 표준 MHA: 각 head 마다 K, V 를 따로 저장 → 메모리 폭증
- MLA: K, V 를 **저차원 latent vector** `c^KV ∈ ℝ^{d_c}` 로 압축해 캐시
- 추론 시 `c^KV` 를 다시 K, V 로 projection

```
c^KV = W^DKV · h           # 압축
K = W^UK · c^KV             # 복원
V = W^UV · c^KV
```

### 효과
- DeepSeek-V2: 67B dense MHA 대비 **KV cache 93.3% 감소** [P10]
- generation throughput **5.76× 향상**

### 한계
- **cache 크기는 줄지만 attention 계산은 여전히 O(n²)** (모든 K, V 와 dot product)
- 1M context 에서 FLOPs 폭발은 그대로

---

## 3단계: 전 단계 (2) — DSA (V3.2): Sparsity

**DeepSeek Sparse Attention (DSA)** (V3.2, 2025년 9월, [P11]) — 희소화의 시도:

### 핵심 아이디어
- 모든 preceding token 에 attend 하지 말고, **top-k 개만 선택**
- 선택은 가벼운 "**Lightning Indexer**" 로 수행

```
1. Lightning Indexer 가 query 와 모든 KV 에 대해 빠르게 score 계산
2. score top-k 의 KV 만 골라 dense attention
```

### 효과 [P11]
- attention FLOPs **O(n²) → O(n·k)** (k ≪ n)
- per-layer attention compute **1.5× ~ 2× 감소**
- 1M context 에서 end-to-end GPU cost 절반

### 한계
- KV cache 자체는 여전히 **모든 n 개** 저장 (sparse 는 선택일 뿐)
- 비선택 token 의 정보 영구 손실 (sliding window 같은 보완 없으면)

---

## 4단계: V4 의 통찰 — 압축과 희소를 결합하면?

> 단순 sparse: 비선택 token 정보 잃음 → long-range dependency 약화
> 단순 compression: fine-grain 정보 평균화로 손실
> → **둘을 결합하면? + 두 종류 attention 을 interleaved 하면?**

V4 의 답:
- **CSA**: 중간 압축 (m=4) + sparse top-k → fine-grain + 정밀 선택
- **HCA**: 강한 압축 (m'=128) + dense → 거시적 long-range coverage
- 두 layer 를 **interleaved 배치** → 둘 다 cover

---

## 5단계: CSA (Compressed Sparse Attention) 상세

### Step A — KV 압축

입력 hidden states `H ∈ ℝ^{n×d}` 에서 두 종류 KV entries 와 그들의 weight 생성:

```
C^a = H · W^aKV    C^b = H · W^bKV       # KV 쌍 (∈ ℝ^{n×c})
Z^a = H · W^aZ     Z^b = H · W^bZ        # 압축 weight (∈ ℝ^{n×c})
```

**m=4 개 KV entries 를 1 개로 압축**:

```
[S^a; S^b] = Softmax_row([Z^a + B^a; Z^b + B^b])    # m+m=8개 weight 합쳐 정규화
C_i^Comp = Σ S^a_j ⊙ C^a_j  +  Σ S^b_j ⊙ C^b_j     # weighted sum
```

- `B^a, B^b` 는 학습 가능 positional bias
- 결과: 시퀀스 길이가 `n/m = n/4` 로 단축

> **Key insight**: 단순 stride 가 아니라 **learnable weighted sum** 으로 압축. positional bias 가 m 개 안에서의 위치 정보 보존.

### Step B — Lightning Indexer 로 sparse 선택

압축된 entry 들 (`C^Comp` 의 n/m 개) 중에서 query 와 가장 관련성 높은 **top-k** 만 선택:

```
# Indexer 의 query 생성 (low-rank)
c_t^Q = h_t · W^DQ                                # latent
[q_{t,1}^I; ...; q_{t,n_h^I}^I] = c_t^Q · W^IUQ   # n_h^I 개 indexer query head

# 압축된 entry 에 대한 indexer key (재사용 압축)
K^IComp = (압축된 indexer key, ∈ ℝ^{n/m × c^I})

# Index score (가벼운 ReLU 기반)
[w_{t,1}^I; ...] = h_t · W^w
I_{t,s} = Σ_h w_{t,h}^I · ReLU(q_{t,h}^I · K_s^IComp)

# Top-k 선택
C_t^SprsComp = { C_s^Comp | I_{t,s} ∈ Top-k }
```

> **Lightning** 인 이유: indexer head 수가 적고 (V4 는 64 개), **FP4 양자화**로 매우 빠름.

### Step C — Shared KV MQA Core Attention

선택된 압축 KV 에 대해 **Multi-Query Attention** (Shazeer 2019, [P12]) 으로 attend:

```
[q_{t,1}; ...; q_{t,n_h}] = c_t^Q · W^UQ           # query 생성 (Indexer query 와 c_t^Q 공유)
o_{t,i} = CoreAttn(query=q_{t,i}, key=value=C_t^SprsComp)
```

- MQA: 모든 query head 가 single key/value 공유 → 압축된 KV 효율
- query 도 indexer 와 same latent `c_t^Q` 사용 → 추가 비용 없음

### Step D — Grouped Output Projection

n_h 개 head output 을 그룹 g 개로 묶어 projection:
- 직접 d 차원으로 projection 하면 `c·n_h × d` 큰 행렬
- 그룹화하면 비용 ↓, 표현력 거의 유지

### CSA 효율 요약
- 시퀀스 1/m 압축 (m=4) → KV cache 1/4
- top-k sparse → FLOPs 추가로 줄임
- "**4× compression × top-k sparsity**" → 실효 비용 매우 낮음

## 6단계: HCA (Heavily Compressed Attention) 상세

CSA 와 같은 패턴이지만 **더 강한 압축**, 그리고 **sparse 선택 없음**.

### 압축 (m' = 128)

```
C = H · W^KV        # ∈ ℝ^{n × c}
Z = H · W^Z

S = Softmax_row(Z + B)              # m'=128 개 weight 정규화
C_i^Comp = Σ S_j ⊙ C_j               # 128 개 → 1 개 압축
```

- 시퀀스 길이가 `n/128` 로 단축 (CSA 의 32배 더 압축)
- 1M context → 7800 entries 만 남음

### Dense MQA

압축된 entry 모두에 대해 **dense attention**:

```
o_{t,i} = CoreAttn(query=q_{t,i}, key=value=C^Comp)   # 모든 entry 사용
```

→ top-k 없음. 압축으로 이미 작아서 dense 로 충분.

### 왜 sparse 없이?
- 128 압축 후 entries 가 7800 개로 충분히 작음
- sparse top-k 추가하면 indexer overhead 가 dense attention 비용을 초과
- **거시적 정보를 빠짐없이 보기** 가 HCA 의 목적

---

## 7단계: Hybrid 전략 — Why interleaved?

V4 는 **CSA layer 와 HCA layer 를 interleaved** 배치:

| 모델 | 첫 layers | 이후 |
|---|---|---|
| V4-Flash (43L) | 처음 2 개 layer: pure sliding window | 41 layer: CSA·HCA interleaved |
| V4-Pro (61L) | 처음 1 개 layer: HCA | 60 layer: CSA·HCA interleaved |

### 왜 interleaved?

- **CSA only**: 모든 layer 에서 fine-grain 보존하지만 거시적 long-range는 sparse top-k 가 놓칠 수 있음
- **HCA only**: 거시적 long-range 는 cover 하지만 fine-grain 손실
- **Interleaved**: layer 마다 두 시각을 번갈아 → 두 정보 다 누적

→ 시각 차이를 **정보 처리 흐름의 다양성** 으로 활용.

## 8단계: 추가 트릭들 (§2.3.3 Other Details)

### (a) Q/K RMSNorm

CSA·HCA 모두 query 와 KV entry 의 단일 head 에 RMSNorm 적용
- 효과: attention logit 폭주 방지
- → Muon 의 QK-Clip 불필요해짐 (§2.4 와 시너지)

### (b) Partial RoPE (마지막 64 dim 만)

- 표준 RoPE: query/key 모든 dim 에 회전 → 압축된 KV 와 호환 어려움
- V4: query·KV·core attention output 의 **마지막 64 dim 만 RoPE** 적용
- output 에 추가로 RoPE(-i) 적용 → 상대 거리 정보 보존

### (c) Sliding Window Attention (보조 branch)

- CSA·HCA 는 압축 단위(m, m') 안의 토큰 정보를 평균화 → 직전 토큰의 fine dependency 손상 위험
- **추가로 last `n_win=128` 개 uncompressed KV 를 보관**
- core attention 시 `C_t^SprsComp` 와 함께 attend
- → "거시 (압축) + 미시 (sliding window)" 결합

### (d) Attention Sink (Xiao et al. 2024, [P13])

**문제**: softmax 의 합이 1 강제 → 모든 query 가 어딘가에 attention 을 "버려야" 함. 일반적으로 첫 몇 token 으로 가는데, 이게 streaming/long-context 에서 깨지면 모델 무너짐.

**해법**: 학습 가능한 **sink logit** `z_h^*` 를 softmax denominator 에 추가:

```
s_{h,i,j} = exp(z_{h,i,j}) / (Σ_k exp(z_{h,i,k}) + exp(z_h^*))
```

- 합이 1 미만이어도 OK → "버릴 곳" 따로 마련
- attention head 가 강제로 어딘가에 집중하지 않아도 됨
- StreamingLLM [P13] 이 도입한 트릭, V4 가 채택

---

## 9단계: 효율성 정량 분석

§2.3.4 의 핵심 메시지:

### KV cache 크기
- BF16 GQA8 (head_dim=128) 표준 baseline 대비 V4 series 의 KV cache 는 **~2%** (1M context)
- V3.2 대비도 V4-Pro 가 10%, V4-Flash 가 7%

### Mixed precision
- RoPE 차원: BF16 (정밀도 중요)
- 나머지 차원: FP8
- Indexer attention: **FP4** (Lightning indexer 의 핵심 가속)

### 작은 top-k
- V3.2 보다 작은 top-k → short/medium context 에서 더 효율
- 1M context 에서도 충분 (이미 압축이 강하므로)

---

## 정리 — §2.3 한눈에 보기

| 시기 | 기법 | KV cache | FLOPs | 한계 |
|---|---|---|---|---|
| V2 / V3 | **MLA** [P10] | 1/15 (vs MHA) | O(n²) 그대로 | 계산 비용 ↓ 못함 |
| V3.2 | **DSA** [P11] | n 그대로 | O(n·k) | cache 크기 ↓ 못함 |
| **V4** | **CSA** | n/m (압축) | top-k (sparse) | 둘 다 절감 |
| **V4** | **HCA** | n/m' (강압축) | dense (작음) | 거시 cover |

**CSA + HCA + sliding window + attention sink** 의 결합으로 V3.2 대비 1M context FLOPs **27%**, KV **10%** 달성.
