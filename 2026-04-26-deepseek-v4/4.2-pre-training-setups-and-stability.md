# §4.2 Pre-Training Setups & Mitigating Training Instability — 차근차근

V4 의 32T+ 토큰 학습을 **무사히 끝낸** 이야기. 모델 hyperparameter 보다 **trillion-scale 학습의 instability 와 그 해결** 이 중요한 contribution.

---

## 1단계: 출발점 — V4 의 모델 / 학습 hyperparameters

### V4-Flash (총 284B / 활성 13B)
- **43 Transformer layers**, hidden dim **d=4096**
- **첫 2 layer**: pure sliding window attention
- **나머지 41 layer**: CSA·HCA interleaved
- **CSA**: m=4, indexer head 64 개, top-k=512
- **HCA**: m'=128
- **MoE**: 1 shared + 256 routed, 6 활성, expert hidden dim 2048
- **첫 3 MoE layer**: Hash routing (§2.1)
- **mHC**: n_hc=4, Sinkhorn-Knopp 20 회
- **MTP depth**: 1
- **학습**: 32T 토큰

### V4-Pro (총 1.6T / 활성 49B)
- **61 layers**, hidden dim **d=7168**
- **첫 1 layer**: HCA only
- **나머지 60 layer**: CSA·HCA interleaved
- **CSA**: m=4, top-k=1024
- **HCA**: m'=128
- **MoE**: 1 shared + 384 routed, 6 활성, expert hidden dim 3072
- **mHC**: n_hc=4
- **학습**: 33T 토큰

### 학습 schedule (둘 다)
- AdamW: β1=0.9, β2=0.95, ε=10^-20, weight_decay=0.1
- Muon: momentum=0.95, weight_decay=0.1, RMS rescale γ=0.18
- **Batch size 스케줄링**: 작게 시작 → **75.5M tokens** (Flash) / 94.4M tokens (Pro) 까지 증가
- **Sequence length curriculum**: 4K → 16K → 64K → **1M**
- **Sparse attention 도입 시점**: 처음 1T 토큰은 dense, 64K sequence 부터 sparse

→ "**조건이 안정될 때 까지 단순히 진행, 그 후 어려운 단계 추가**" 의 curriculum.

## 2단계: 핵심 도전 — Loss Spike

### 무엇이 문제인가

> "Training trillion-parameter MoE models presents significant stability challenges, and DeepSeek-V4 series are no exception. We encountered notable instability challenges during training." — V4 paper §4.2.3

**Loss spike** = 학습 진행 중 loss 가 갑자기 **수십~수백 배 jump** 하는 현상.
- 한 step 안에 numerical anomaly 누적
- 누적되면 모델 quality 영구 손상
- → **학습 실패**

### 기존 대응 (보편적)

**Rollback**:
- Spike 감지 → 직전 checkpoint 로 되돌리기
- 일시적 회복은 가능
- 그러나 V4 paper:
  > "they proved inadequate as a long-term solution because they do not prevent the recurrence of loss spikes"
- → 같은 자리에서 또 spike 발생, 학습 진행 안 됨

### V4 의 진단

> "the occurrence of spikes is consistently tied to outliers in the MoE layers, and the routing mechanism itself appears to exacerbate the emergence of these outliers"

→ MoE 의 routing 자체가 spike 의 원인.

---

## 3단계: V4 의 두 가지 Stabilization 트릭

V4 는 두 가지 새 기법으로 spike 를 **근본 차단**:
1. **Anticipatory Routing** — routing 의 vicious cycle 차단
2. **SwiGLU Clamping** — outlier 직접 억제

### (a) Anticipatory Routing — Routing 의 vicious cycle 차단

**핵심 아이디어**:
- Spike 발생 = 순간적 outlier activation 이 routing 에 영향 → 더 큰 outlier → 발산
- 이 vicious cycle 을 끊으려면 **routing 결정을 "이전 시점" parameter 로** 분리

**구현**:
- Step `t` 의 forward: 현재 parameter `θ_t` 사용
- 그러나 **routing index 는 historical parameter `θ_{t-Δt}` 로 미리 계산**
- 이름의 유래: "**anticipatorily** compute and cache routing indices to be used later"

**구현 효율**:
- naive: parameter 두 번 load (θ_t, θ_{t-Δt}) → 비용 ↑
- V4: pipeline 미세 조정 + EP 통신과 overlap
- **추가 wall-clock overhead 약 20%**

**자동 트리거**:
- 평소: standard training (overhead 0)
- Loss spike 감지: short rollback + Anticipatory Routing 활성
- 일정 기간 후 standard 로 복귀
- → 평균 overhead **negligible**

**결과**: spike 회피 + 모델 성능 손실 없음.

### (b) SwiGLU Clamping — Outlier 직접 억제

**SwiGLU 의 구조** [P39]:
```
SwiGLU(x) = (x · W_gate) ⊗ Swish(x · W_up)
            └─ linear ─┘   └─ activated ─┘
```

**문제**: linear component (`x · W_gate`) 또는 activated component (`Swish(x · W_up)`) 가 **outlier 생성** 가능
- 이 outlier 가 다음 layer 의 routing 을 흔들고 spike 유발

**기존 해법**: PaLM 등에서 사용한 **clipping** (Bello et al. 2017, Riviere et al. 2024 [P47])

**V4 의 적용**:
> "we clamped the linear component of SwiGLU to the range of [-10, 10], while capping the upper bound of the gate component at 10"

- Linear: `[-10, 10]` 범위로 clip
- Gate: 상한 10
- 이 범위 안에서는 모델 자유도 유지
- 범위 벗어나는 값은 강제 truncation

**효과**:
- Outlier substantially 제거
- Training stabilization
- 모델 성능 손실 미미

## 4단계: 두 트릭이 함께 작동

V4 paper 의 메시지:
> "Although Anticipatory Routing and SwiGLU Clamping have been proven effective in mitigating training instabilities, **their underlying principles remain insufficiently understood**. We will actively study foundational problems on training stability"

→ V4 자체가 "공학적으로 작동하지만 이론적 이해가 부족" 임을 인정.

### 두 기법의 복합 효과
- Anticipatory Routing: routing 자체의 self-reinforcing 차단
- SwiGLU Clamping: outlier source 자체 차단
- **둘 다 적용** 시 spike 발생 거의 사라짐

→ V4 series 가 32T+ 토큰을 **학습 실패 없이 완주** 한 핵심 이유.

---

## 5단계: 다른 학습 디테일

### Auxiliary-loss-free balancing parameters
- Bias update speed γ = 0.001
- Sequence-wise balance loss weight = 0.0001 (V4 의 추가, §2.1 참고)

### MTP loss weight
- 학습 대부분: 0.3
- LR decay 시작 시점부터: 0.1
- → 학습 후반에는 main LM loss 우선

### Sparse attention warmup
- 첫 1T 토큰: dense attention only
- 이후 64K sequence 진입 시 sparse attention 도입
- 도입 직전: short stage 로 lightning indexer 만 warmup
- 그 후 sparse attention training

### LR decay
- Cosine schedule
- Peak LR: 2.7×10^-4 (Flash) / 2.0×10^-4 (Pro)
- End LR: 2.7×10^-5 (Flash) / 2.0×10^-5 (Pro)

---

## 6단계: 왜 이 부분이 중요한가? (Meta-insight)

### Trillion-scale 학습의 본질적 문제

대규모 모델 학습은 **체인 안정성 문제**:
- 한 step 의 anomaly = 전체 학습 망가짐
- Rollback 만으로는 근본 해결 안 됨
- **사전 stability mechanism** 이 결정적

### V4 가 보여주는 패러다임

1. **검증된 안정화 기법** (§3.3 의 deterministic kernel, §2.2 의 mHC manifold constraint) 이 *base*
2. **추가로 학습 시 emergent 안정화** (§4.2.3 의 Anticipatory Routing, SwiGLU Clamping) 이 *adaptive*
3. **이론적 이해는 후속 연구** — 일단 작동하면 채택

→ Trillion-scale 모델은 **이론보다 경험적 stabilization** 의 영역.

### Industry impact

- Anticipatory Routing 은 **MoE 학습 안정화의 새 표준** 이 될 가능성
- SwiGLU Clamping 은 이전 PaLM 의 clamp 와 다른 구체적 schema [P47]
- 두 방법 모두 V4 paper 가 처음 정량적으로 보고

## 정리 — §4.2 한눈에 보기

| 항목 | 기존 방식 | V4 |
|---|---|---|
| Loss spike 대응 | rollback | **Anticipatory Routing + SwiGLU Clamping** (사전 차단) |
| Anticipatory Routing | — | routing 을 θ_{t-Δt} 로 분리 → vicious cycle 차단 |
| SwiGLU Clamping | clip without specifics | linear `[-10,10]`, gate 상한 10 |
| Sequence curriculum | 표준 | 4K → 16K → 64K → 1M (점진적) |
| Sparse attn 도입 | initial 부터 | **dense 1T 토큰 후** sparse 도입 (warmup 단계 추가) |
| Batch size schedule | 표준 | 작게 → 큰 75.5M / 94.4M tokens |
| Stability 이론 | — | "**작동하지만 이해 부족**" 명시, 후속 연구 promise |

**핵심 통찰**:
1. **Trillion-scale 학습은 stability 가 핵심**. 모델 hyperparameter 보다 spike 차단 mechanism 이 더 결정적.
2. V4 의 두 stabilizer (**Anticipatory Routing, SwiGLU Clamping**) 가 32T+ 학습을 가능하게 만든 결정타.
3. Routing 의 **self-reinforcing nature** 가 MoE 의 본질적 instability 원인 — V4 가 처음 명시.
4. **이론 < 경험** 의 단계임을 V4 가 솔직히 인정 (후속 연구 promise).
5. 학습 curriculum (4K→1M) 이 안정성과 효율의 sweet spot.
