# §3.4 FP4 Quantization-Aware Training — 차근차근

V4 의 메모리·연산 효율을 한 단계 더 끌어내린 핵심 기법. **4-bit floating point 로 학습까지 진행** 한다는 도전.

---

## 1단계: 출발점 — Floating Point Format 의 역사

### 표준 LLM precision 의 흐름

| 시기 | format | 메모리/param | 비고 |
|---|---|---|---|
| 2017~ | FP32 | 4 bytes | 표준, 안정 |
| 2018~ | FP16 (mixed) | 2 bytes | NVIDIA Tensor Core 가속, AMP 도입 |
| 2020~ | BF16 | 2 bytes | exponent ↑ 로 dynamic range 보존 |
| 2024~ | FP8 (E4M3/E5M2) | 1 byte | H100 hardware 지원 |
| 2025~ | **FP4 (MXFP4)** | **0.5 byte** | B200 hardware 지원, 도전적 |

→ "더 작은 precision" 이 메모리·연산 효율의 핵심.

### 4-bit 의 도전

- E2M1 (1 sign + 2 exponent + 1 mantissa) → **표현 가능 값 16 개**
- 단순 cast 하면 **모델 quality 붕괴**
- 특히 **outlier activation** 이 4-bit 으로 표현 불가 → 정보 손실 큼

---

## 2단계: 전 단계 — Microscaling (MX) Format

### MXFP4 (Microscaling FP4) [P31]

**핵심 아이디어**: block-wise shared scale

```
원본 array: [x_1, x_2, ..., x_32]  (32 개 element)
저장 형태:
  - 각 element: FP4 (0.5 byte)  → 16 bytes
  - 공유 scale: E8M0 또는 E4M3 (1 byte)  → 1 byte
  Total: 17 bytes (vs FP32 128 bytes)
```

- block 마다 (예: 32 element) **하나의 scale** 공유
- 각 block 안의 dynamic range 가 좁다면 효과적
- block size 32: MXFP4 표준
- block size 16: NVFP4 (NVIDIA 변종, 더 정밀)

### MX format 의 효과
- naive FP4 보다 정확도 손실 ↓
- HW 지원 (B200) 시 매우 빠름
- 그러나 **outlier-heavy activation 에서는 여전히 손실**

---

## 3단계: V4 의 적용 영역 — 모든 곳이 아닌 *선택적*

### 적용 대상 (V4 paper §3.4)

1. **MoE expert weights** (가장 큰 메모리 영역)
   - 1.6T 모델의 99% 이상이 MoE weights
   - FP4 → 메모리 4× 절감 가능

2. **CSA Indexer 의 QK path** (§2.3 의 Lightning Indexer)
   - Indexer 의 QK 활성·load·multiply 모두 FP4
   - long context 에서 attention score 계산 가속

### 적용 *안 한* 영역
- Attention 의 main path KV cache (BF16/FP8 mix)
- Embedding, prediction head
- LayerNorm, mHC 의 small parameter

→ **민감한 곳은 보존, 영향 큰 곳만 양자화**.

---

## 4단계: QAT (Quantization-Aware Training) 의 메커니즘

### Post-Training Quantization (PTQ) vs QAT

**PTQ** (사후 양자화):
- 학습 끝낸 모델을 4-bit 로 cast
- 빠르지만 quality 손실 큼
- 특히 4-bit 같이 극단적 양자화에서 부적합

**QAT** (양자화 인식 학습):
- **학습 중에** quantize/dequantize 시뮬레이션
- 모델이 quantization 손실을 *학습* 으로 보상
- → 더 robust 한 양자화 모델

### V4 의 QAT 흐름

**Forward pass**:
```
FP32 master weight (optimizer 가 유지)
   ↓ quantize
FP4 weight (계산용)
   ↓ dequantize
FP8 weight (실제 forward 계산)
```

- **FP4 → FP8 dequantize 가 lossless** (V4 의 핵심 발견)
- 이유: FP4 (E2M1) 의 sub-block scale 과 FP8 (E4M3) 의 dynamic range 가 매칭

**Backward pass**:
- gradient 는 FP8 weight 기준으로 계산
- FP32 master weight 으로 back-propagate (Straight-Through Estimator [P32])
- **추가 dequantization 없음** (FP8 forward 결과 재사용)

### Lossless 조건 (V4 의 발견)

> "as long as the ratio between the maximum and minimum scale factors of the FP4 sub-blocks (1×32 tiles) within each FP8 quantization block (128×128 tiles) does not exceed a certain threshold, the fine-grained scale information can be fully absorbed by the extended dynamic range of FP8."

- FP4 sub-block: 32 element
- FP8 outer block: 128×128
- 두 scale 의 ratio 가 threshold 이하면 → FP4→FP8 dequantize 가 정보 손실 없음
- V4 는 실험으로 weight 가 이 조건 만족함을 확인

→ 이 발견 덕에 **기존 FP8 학습 파이프라인 변경 없이 FP4 통합** 가능.

## 5단계: Indexer Score 의 FP4 양자화

### Lightning Indexer 의 score I_t,s

§2.3 에서 본 indexer score:
```
I_{t,s} = Σ_h w_{t,h}^I · ReLU(q_{t,h}^I · K_s^IComp)
```

**기존**: 이 score 를 FP32 로 계산
**V4**: BF16 로 양자화

- top-k selector 가 **2× 빠름**
- KV entries 의 recall rate **99.7%** (거의 손실 없음)
- → long-context 에서 substantial 가속

---

## 6단계: 추론·Rollout 에서의 활용

### Inference / RL Rollout
- forward pass 만 필요 (backward 없음)
- → **simulated dequantization 불필요, 직접 FP4 weight 사용**
- 효과:
  - kernel memory loading ↓
  - actual speedup
  - 메모리 사용량 ↓

### Deployment 일관성
- 학습 시 FP4 quantize 된 weight 로 forward 시뮬
- 추론 시 같은 FP4 weight 직접 사용
- → **training-inference behavior 일관**

---

## 7단계: 다른 FP4 시도와의 비교

| 접근 | 특징 | 차이 |
|---|---|---|
| **PTQ FP4** (대부분의 LLM) | 학습 후 cast | quality 큰 손실 |
| **AMXFP4** [P33] | asymmetric scale | activation outlier 처리 |
| **FP4 fully quantized training** [P34] | weight + activation 모두 FP4 | 매우 도전적, V4 와 다른 방향 |
| **V4 의 QAT** | weight + indexer 만 FP4, activation 보존 | **lossless dequant 발견** + production-ready |

---

## 정리 — §3.4 한눈에 보기

| 항목 | V4 의 선택 | 이유 |
|---|---|---|
| 적용 영역 | MoE weight + CSA indexer QK | 메모리·연산 영향 큰 곳 |
| 적용 *안* 한 곳 | Embedding, head, attention main, mHC | 민감, 작아서 효과 적음 |
| 양자화 형식 | **MXFP4** (E2M1, block 32) | 표준, B200 지원 |
| 학습 방식 | **QAT** (FP32 master, FP4 forward sim, FP8 dequant lossless) | quality 보존 |
| 추론 시 | **실제 FP4 weight 사용** | 가속 + 메모리 ↓ |
| Indexer score | FP32 → BF16 | 2× 가속, recall 99.7% |
| 적용 시점 | **Post-training stage** | base 학습 후 적응 |

**핵심 통찰**:
1. **모든 곳을 FP4 로 양자화 ≠ 좋은 선택**. 영향이 큰 영역만 선택.
2. V4 의 핵심 발견: **FP4→FP8 dequantize 가 일정 조건 하에 lossless** → 기존 FP8 파이프라인 무변경
3. **QAT > PTQ** for 4-bit. 학습 중 양자화 시뮬이 quality 보존의 결정타.
4. Indexer 의 BF16 양자화는 **score 정확도와 속도 trade-off** 를 sweet spot 에서 잡음 (recall 99.7%).
5. Production 효과: 메모리 ↓, training-inference 일관성, B200 같은 미래 hardware 활용.
