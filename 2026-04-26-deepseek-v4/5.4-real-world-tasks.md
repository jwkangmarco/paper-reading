# §5.4 Performance on Real-World Tasks — 차근차근

표준 benchmark 가 측정하지 못하는 **실제 사용 시나리오** 에서 V4 의 능력 검증. V4 paper 의 가장 "production-aware" 평가.

---

## 1단계: Motivation — Standard Benchmark 의 한계

V4 paper §5.4:
> "Standardized benchmarks often struggle to capture the complexities of diverse, real-world tasks, creating a gap between test results and actual user experience."

### Benchmark vs Real-World 의 격차
- HLE, GPQA: 학술적 어려움 우선
- SWE-bench: GitHub issue 의 단순한 버그 fix
- Real user query: ambiguous, multi-turn, formatting 요구, 한국어/중국어 같은 비영어, 도메인 specialized

### V4 의 접근

**4 가지 real-world 영역** 에 자체 평가:
- §5.4.1 **중국어 글쓰기** (Chinese Writing)
- §5.4.2 **검색 증강 답변** (Search)
- §5.4.3 **White-Collar 업무** (전문가 문서 작업)
- §5.4.4 **Code Agent** (R&D 개발 task)

→ DeepSeek API + Chatbot 의 primary use case 에 align 한 평가.

## 2단계: §5.4.1 Chinese Writing — Functional + Creative

### 평가 setup
- Functional writing: 보고서, 제안서, 교육, 이메일, 모집 공고 등 **3,170 sample**
- Creative writing: 소설, 시, 산문 등 **2,837 sample**
- Pairwise comparison vs **Gemini-3.1-Pro** (top external model in Chinese writing)
- 인간 평가자 blind judging

### Functional Writing 결과 (Table 12)

전체: **DS Win 62.65%**, Gem Win 34.10%, Tie 3.25%

세부:
| 카테고리 | DS Win | Gem Win |
|---|---|---|
| Business Writing (1349 sample) | 65.16% | 32.32% |
| Media Writing (666) | 57.96% | 38.44% |
| Everyday Writing (390) | 69.49% | 25.90% |
| Oral Writing (319) | 58.62% | 37.62% |
| Official Document (230) | 54.78% | 42.17% |
| Academic Writing (216) | **63.43%** | 32.87% |

→ **거의 모든 카테고리에서 DS-V4-Pro 우세**. 학술 문서 카테고리 별로 강점.

### Creative Writing 결과 (Table 13)

| 평가 차원 | DS Win | Gem Win |
|---|---|---|
| Instruction Following | 60.03% | 39.44% |
| Writing Quality | **77.48%** | 22.35% |

→ Writing Quality 에서 +55% 우위. Instruction Following 에서도 +20%.

### V4 paper 의 분석

> "Gemini occasionally allows its inherent stylistic preferences to override the user's explicit requirements in Chinese writing scenarios"

- Gemini 는 자기 stylistic preference 에 의해 user 요구를 override
- V4 는 user 의 explicit requirement 더 충실 따름

### V4 의 약점 — Complex Multi-Turn (Table 14)

V4-Pro vs **Claude Opus 4.5** 의 어려운 케이스 (196 sample):
- Complex Instruction Following: DS 46.9%, Opus **53.1%**
- Multi-Turn Writing: DS 45.6%, Opus **51.7%**
- 전체: DS 45.9%, Opus **52.0%**

→ **Frontier closed model 의 multi-turn complex task 우위**가 여전히 존재.

## 3단계: §5.4.2 Search — RAG vs Agentic

### Two modes
- **Non-think mode**: Retrieval-Augmented Search (RAG)
- **Think mode**: Agentic Search

### RAG: V4-Pro vs V3.2 (Table 11)

전체 956 sample:
- DS-V4-Pro Win: 28.1%
- V3.2 Win: 10.4%
- Tie: 61.5%

세부:
| Subcategory | V4 Win | V3.2 Win | Tie |
|---|---|---|---|
| Single-value Search (95) | **37.9%** | 10.5% | 51.6% |
| Entity Search (99) | 24.2% | 7.1% | 68.7% |
| Causal Analysis (100) | 28.0% | 5.0% | 67.0% |
| Comparison (96) | 29.2% | 20.8% | 50.0% |
| Recommendation (95) | 27.4% | 20.0% | 52.6% |
| Planning & Strategy (92) | 34.8% | 12.0% | 53.3% |
| Trend Analysis (96) | 24.0% | 3.1% | 72.9% |

→ V4-Pro 가 V3.2 대비 **substantial 우위**. 특히 single-value, planning, trend analysis 가 강점.

### Agentic Search vs RAG (Table 9)

DS-V4-Pro 자체 비교, 869 sample:

| Difficulty / Category | Agent Win | RAG Win | Tie |
|---|---|---|---|
| Easy / Objective Q&A (196) | 56.1% | 21.9% | 21.9% |
| Easy / Subjective Q&A (321) | 61.7% | 17.4% | 20.9% |
| Hard / Objective Q&A (168) | 60.7% | 19.6% | 19.6% |
| Hard / Subjective Q&A (184) | **68.5%** | 14.7% | 16.8% |
| **Total (869)** | **61.7%** | 18.3% | 20.0% |

→ **Agentic 이 거의 모든 케이스에서 RAG 능가**. 특히 어려운 subjective 질문에서 +54%.

### Cost Comparison (Table 10)

평균 per request:
- V4 Agentic: **16.2 tool calls**, 13,649 prefill tokens, 1,526 output
- V4 RAG: 0 tool calls, 10,453 prefill, 1,308 output

→ Agentic 은 RAG 보다 **약간만 비싸** (prefill 30% ↑, output 17% ↑) 하면서도 win-rate 큰 폭 ↑.

## 4단계: §5.4.3 White-Collar Task — 전문가 문서 작업

### Setup
- **30 advanced Chinese professional tasks**
- 13 critical industries (finance, education, law, technology 등)
- High-level cognitive demands: in-depth analysis, comprehensive document generation, nuanced editing
- In-house agent harness (bash + web search)
- Human evaluation, **Opus 4.6 Max 와 비교**

### 4 차원 평가
- **Task Completion**: 핵심 문제 해결
- **Instruction Following**: 명령 준수
- **Content Quality**: 정확성, 논리 일관성, 전문 톤
- **Formatting Aesthetics**: 가독성, 시각

### Win-rate (Figure 11)

| 차원 | DS Win | Tie | Opus Win |
|---|---|---|---|
| Analysis | 55.0% | 8.0% | 37.0% |
| Generation | 52.0% | 10.0% | 38.0% |
| Editing | 47.0% | 18.0% | 35.0% |
| **Overall** | **53.0%** | **10.0%** | **37.0%** |

→ Non-loss rate 63% (V4 가 지지 않은 비율).

### Detailed Score (Figure 12)

| 차원 | DS-V4 | Opus |
|---|---|---|
| Task Completion | **98.32** | 96.68 |
| Instruction Following | 87.76 | **88.88** |
| Content Quality | **83.32** | 78.00 |
| Formatting Aesthetics | 76.78 | **72.68** |
| Overall | **86.52** | 84.06 |

### V4 의 강점
- **Task Completion + Content Quality**: 명확한 우위
- 사용자 implicit intent 능동적 파악, supplementary insights 자주 제공
- Long-form generation 에서 깊이 있고 일관성 있는 narrative
- 형식적 컨벤션 (예: 중국식 hierarchy numbering) 엄격 준수

### V4 의 약점
- Instruction Following: Opus 가 약간 우위 (specific formatting constraint 놓침)
- 긴 input 을 succinct summary 로 압축하는 능력 부족
- Presentation slide 의 visual design 개선 여지

## 5단계: §5.4.4 Code Agent — V4 의 가장 강력한 영역

### Setup
- ~200 challenging tasks from real DeepSeek **internal R&D workloads**
- 50+ internal engineer 의 일상 업무
- Feature dev, bug fix, refactoring, diagnostics
- Stacks: PyTorch, CUDA, Rust, C++
- Each task: original repo + execution env + human-annotated rubric
- 30 task selected for evaluation

### 결과 (Table 8)

| Model | Pass Rate (%) |
|---|---|
| Haiku 4.5 | 13 |
| Sonnet 4.5 | 47 |
| **DS-V4-Pro-Max** | **67** |
| Opus 4.5 | 70 |
| Opus 4.5 Thinking | 73 |
| Opus 4.6 Thinking | **80** |

### 위치
- **Sonnet 4.5 능가** (+20pt)
- **Opus 4.5 에 근접** (-3pt)
- Opus 4.6 Thinking (frontier) 에는 -13pt

### 내부 dev 설문 (N=85)
- 52% "yes, V4-Pro 를 default coding 모델로 채택"
- 39% "yes (lean toward)"
- < 9% "no"

→ DeepSeek 내부 사용자가 직접 검증한 **production-grade coding 능력**.

### 한계 (응답에서 언급)
- Trivial mistakes (간단한 실수)
- Misinterpretation of vague prompts
- Occasional over-thinking

→ Frontier 와의 진짜 격차는 **subtle precision** 에 있음.

## 6단계: V4 paper §5.4 의 메타 메시지

### Real-World 평가가 뭘 보여주는가?

1. **Standard benchmark 에서의 격차가 real-world 에서는 다르게 나타남**
   - HLE 등에서 V4 가 Gemini 에 뒤짐 (-6.7)
   - 그러나 중국어 writing 에서 V4 가 Gemini 에 +28% win-rate
   - → **Use case 에 따라 모델의 ranking 다름**

2. **V4 의 "효율성 지향" 이 실용 능력으로 변환됨**
   - Internal R&D coding agent 에서 67% (Opus 4.5 의 95% 수준 성능)
   - White-collar task 에서 Opus 능가
   - → 효율성과 실용 능력은 zero-sum 이 아님

3. **Frontier 와의 격차는 reasoning depth 영역에 한정**
   - HLE/GPQA: subtle reasoning, expert knowledge
   - 이쪽에서 Gemini-3.1-Pro / Opus 4.6 우위
   - 그 외 (writing, coding, agent, search): V4 동급 또는 우위

4. **Multi-turn complex 가 V4 의 약점** (Table 14, Opus 4.5 우위)
   - 현재 1M context 능력에도 불구하고 multi-turn complex constraint 처리는 frontier 가 더 정밀

### V4 의 production positioning

V4 paper 가 제시하는 message:
- **Knowledge frontier 1위 ❌** — Gemini-3.1-Pro 차지
- **Code/Agent SOTA 또는 동급** — frontier 진영 안 정착
- **Real-world coding/writing/search**: frontier 동급 + 일부 우위
- **Open weight + 효율적 inference**: deployment 의 차별화

## 정리 — §5.4 한눈에 보기

| Real-world 영역 | V4 의 위치 | 비교 대상 |
|---|---|---|
| **중국어 functional writing** | **DS Win 62.65%** | vs Gemini-3.1-Pro |
| **중국어 creative writing (quality)** | **DS Win 77.48%** | vs Gemini-3.1-Pro |
| **Multi-turn complex** | DS 45.9% | **Opus 4.5 52.0%** (V4 패) |
| **RAG vs V3.2** | **DS Win 28.1%** | (V3.2 10.4%) |
| **Agentic vs RAG (자체)** | Agentic Win 61.7% | (V4 자체 비교) |
| **White-Collar Overall** | **DS Win 53%** | vs Opus 4.6 Max |
| **R&D Coding Agent** | **67%** | Sonnet 4.5 47, Opus 4.5 70, Opus 4.6 Thinking 80 |

**핵심 통찰**:
1. **Real-world 에서 V4 의 위치가 standard benchmark 보다 더 강함** — 효율성 지향이 실용 능력으로 변환
2. **중국어 writing 에서 V4-Pro 가 Gemini-3.1-Pro 능가** — 이 영역에서는 frontier 의 위계가 다름
3. **Agentic search > RAG** 가 cost 적은 차이로 quality substantial ↑
4. **R&D Coding agent**: Opus 4.5 95% 수준, 내부 사용자 90%+ 채택 의향
5. **Frontier 와의 진짜 격차**: multi-turn complex 와 subtle reasoning depth (HLE, GPQA)
6. **Production-grade evaluation 자체가 contribution** — 표준 benchmark 의 한계 명확히 보여줌
