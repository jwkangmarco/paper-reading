# §5.3 Standard Benchmark Evaluation — 차근차근

V4 post-trained 모델의 능력을 어떻게 측정했고 무엇이 강점·약점인지에 대한 정량적 정리.

---

## 1단계: 평가 방법론 — 5 가지 차원

V4 paper §5.3.1 의 평가 차원:

### (a) Knowledge & Reasoning
- MMLU-Pro
- GPQA Diamond
- Human Last Exam (HLE)
- Simple-QA Verified, Chinese-SimpleQA
- LiveCodeBench v6, CodeForces internal
- HMMT 2026 Feb, Apex (Pass@1, Shortlist)
- IMOAnswerBench, PutnamBench

### (b) Code (별도 평가)
- LiveCodeBench-v6 (실시간 contest)
- 14 Codeforces Division 1 contests (May–Nov 2025), 114 problems

### (c) Long-Context (1M)
- OpenAI MRCR (Multi-round Co-reference Resolution)
- CorpusQA

### (d) Agent (8+ benchmarks)
- Terminal Bench 2.0
- SWE-Verified, SWE-Pro, SWE Multilingual
- BrowseComp, HLE w/ tools
- GDPval-AA, MCPAtlas Public
- Tool-Decathlon

### (e) Mathematical formal proving
- Putnam-200 Pass@8 (Practical regime)
- Putnam-2025 (Frontier regime, hybrid formal-informal)
- Lean v4.28.0-rc1 evaluation

→ 평가 자체가 V4 paper 의 contribution 의 일부 — 광범위, 다양한 task family.

## 3단계: Knowledge & Reasoning 결과

### V4-Pro-Max 단독 SOTA / 동률 (오픈모델 중)

| Benchmark | DS-V4-Pro-Max | Opus-4.6 | GPT-5.4 | Gemini-3.1-Pro | K2.6 | GLM-5.1 |
|---|---|---|---|---|---|---|
| MMLU-Pro | 87.5 | 89.1 | 87.5 | **91.0** | 87.1 | 86.0 |
| SimpleQA-Verified | 57.9 | 46.2 | 45.3 | **75.6** | 36.9 | 38.1 |
| Chinese-SimpleQA | 84.4 | 76.4 | 76.8 | **85.9** | 75.9 | 75.0 |
| GPQA Diamond | 90.1 | 91.3 | 93.0 | **94.3** | 90.5 | 86.2 |
| HLE | 37.7 | 40.0 | 39.8 | **44.4** | 36.4 | 34.7 |

**관찰**:
- **오픈모델 중 거의 SOTA**:
  - SimpleQA-Verified: K2.6 36.9, GLM 38.1 → V4 **57.9** (+20)
  - Chinese-SimpleQA: 다른 오픈모델 75 vs V4 **84.4** (+9)
  - GPQA: V4 90.1 ≈ K2.6 90.5
- **Frontier 와의 격차**:
  - Gemini-3.1-Pro 가 knowledge 에서 압도적 (HLE +6.7, SimpleQA +17.7, GPQA +4.2)
  - 이게 V4 paper 의 "**3-6개월 뒤짐**" 표현의 영역

**관찰**:

→ V4 의 **코드 경시 능력은 frontier 진영 안에 정착**.

## 5단계: Long-Context (1M) — Mixed 결과

| Benchmark | DS-V4-Pro-Max | Opus-4.6 | Gemini-3.1-Pro |
|---|---|---|---|
| MRCR 1M | 83.5 | **92.9** | 76.3 |
| CorpusQA 1M | 62.0 | **71.7** | 53.8 |

**관찰**:
- **Gemini-3.1-Pro 능가**: V4 가 MRCR 에서 +7, CorpusQA 에서 +8
- **Opus-4.6 에 뒤짐**: -9 ~ -10 격차
- 일부 영역에서 frontier 와 견주지만 retrieval 정확도는 Opus 가 우위

### MRCR 8-needle test (Figure 9)

Context length 별 average MMR:
- 8K: V4-Pro 0.90, V4-Flash 0.91
- 32K: V4-Pro **0.94**, V4-Flash 0.87 (peak)
- 256K: V4-Pro 0.82, V4-Flash 0.76 (degradation 시작)
- 1024K: V4-Pro **0.59**, V4-Flash 0.49 (large degradation)

→ **128K 까지 안정, 그 이후 급격 저하**. 1M context 가 **이론적 capability** 와 **실제 retrieval 품질** 의 차이를 보여줌.

## 8단계: Reasoning Effort 의 효과 (Figure 10)

V4-Pro/Flash 의 **None / High / Max** mode 비교 (HLE, Terminal Bench 2.0):

### HLE (Pass@1 vs Total tokens)
- DS-V3.2 Speciale: ~30K tokens, 27%
- V4-Flash None: 0K, 8%
- V4-Flash High: 50K, 30%
- V4-Flash Max: 90K, **34%**
- V4-Pro None: 0K, 8%
- V4-Pro High: 30K, 35%
- V4-Pro Max: 80K, **37.7%**

→ **Max mode 가 어려운 task 에서 High 보다 높은 정확도** (token 비용 ↑).
→ V4-Pro 가 V3.2 보다 **token efficient** (같은 정확도 더 적은 token).

### Terminal Bench 2.0
- V4-Pro Max: ~50K tokens, **67.9%**
- 더 적은 token 으로 더 높은 점수 (V3.2 대비).

→ **OPD post-training 의 효과**: 같은 task 에 더 효율적 reasoning.

## 9단계: V4-Flash 와 V4-Pro 의 비교 (Table 7)

| Benchmark | Flash-Non-Think | Flash-Max | Pro-Non-Think | Pro-Max |
|---|---|---|---|---|
| MMLU-Pro | 83.0 | 86.2 | 82.9 | **87.5** |
| HLE | 8.1 | 34.8 | 7.7 | **37.7** |
| LiveCodeBench | 55.2 | 91.6 | 56.8 | **93.5** |
| CodeForces | — | 3052 | — | **3206** |
| MRCR 1M | 37.5 | 78.7 | 44.7 | **83.5** |
| Terminal Bench | 49.1 | 56.9 | 59.1 | **67.9** |

**관찰**:
- **Flash 도 Max mode 에서 매우 강함**: K2.6 등 큰 오픈모델 능가
- Knowledge 는 Pro 가 큰 우위 (param 영향)
- Code 경시는 Flash 도 거의 frontier 수준
- Long context 는 Pro 가 명확히 우위 (활성 49B vs 13B)

→ **V4-Flash 가 cost-effective frontier alternative** 라는 V4 paper 의 메시지를 정량 검증.

## 정리 — §5.3 한눈에 보기

| 차원 | V4-Pro-Max 의 위치 | 격차 |
|---|---|---|
| **Knowledge / Reasoning (raw)** | 오픈모델 SOTA, frontier 와 3-6 개월 격차 | -3 ~ -7pt vs Gemini-3.1-Pro |
| **Code 경시 (CodeForces, LiveCodeBench)** | **Frontier 동급 또는 우위** | +3 ~ +5 pt |
| **Math 경시 (HMMT)** | Frontier 동급 | -2 pt |
| **Long context retrieval** | Gemini 능가, Opus 에 뒤짐 | -9 vs Opus 4.6 |
| **Agent (Terminal/SWE/BrowseComp)** | Frontier 동급 | ±몇 pt |
| **수학 formal proving** | **120/120 SOTA** | proof-perfect |
| **MRCR @ 1M (실제 retrieval)** | 0.59 (큰 degradation) | 1M context 의 이론 vs 실제 격차 |

**핵심 통찰**:
1. **V4 의 강점**: code 경시, formal proving, agent → 학습 cost 대비 명확한 우위
2. **V4 의 약점**: knowledge 의 raw scale (HLE, GPQA Diamond, Apex Pass@1) — frontier 에 3-6 개월 뒤짐
3. **1M context retrieval**: 128K 까지 stable, 그 이후 급격 저하 — 이론 capability 와 실 quality 의 격차
4. **V4-Flash 의 cost-efficiency**: 활성 13B 로 큰 오픈모델 능가
5. **OPD 의 효과**: token-efficient reasoning, Max mode 에서 큰 향상
6. **Open vs Closed 격차**: 일부 영역 (code, agent, formal proving) 에서 격차 거의 사라짐 → **open ecosystem 의 frontier 도달**
