# §2.2 Manifold-Constrained Hyper-Connections (mHC) — 차근차근

§2 에서 가장 까다로운 변경. **"residual connection을 어떻게 일반화하면서도 안정적으로 만들까"** 하는 문제에 대한 V4의 답이다.

---

## 1단계: 출발점 — 표준 Residual Connection

Transformer 의 모든 레이어는 다음 형태:

```
X_{l+1} = X_l + F_l(X_l)
```

- `F_l` 은 attention 또는 FFN/MoE
- `+` 가 **residual connection** — He et al. (2015) 이 ResNet 에서 도입한 트릭

**왜 필요한가?**
- gradient 가 깊은 네트워크에서 vanishing 되는 것 방지
- "변화량 학습" — 레이어가 입력을 *변형*하기보단 *조정*하도록

**한계 (오랜 시간 알려진 문제):**
1. **Gradient vanishing** ↔ **representation collapse** 의 trade-off — Hyper-Connections 논문 [P6] 이 "**seesaw effect**" 라 명명
2. 모든 레이어가 같은 shape (`d` 차원) 의 residual stream 을 공유 → flexibility 부족
3. 깊이가 늘어나면 residual의 신호 세기가 발산하거나 collapse

→ "residual의 단순한 형태가 발목을 잡는다" 는 인식이 2024년부터 본격적으로 제기됨.

---

## 2단계: 전 단계 — Hyper-Connections (HC)

Zhu et al., ICLR 2025 "Hyper-Connections" [P6] 가 V3 시리즈 후반부에 도입된 전구 기술.

### 핵심 아이디어

**residual stream 의 "width" 를 hidden dim 과 분리**:

- 표준: residual stream ∈ ℝ^d
- HC: residual stream ∈ ℝ^{n_hc × d} (n_hc = expansion factor, 예: 4)

레이어 input/output 은 여전히 ℝ^d 이지만, 그 사이의 residual은 더 두꺼움.

### 수식

세 개의 학습 가능 매핑:
- **A_l ∈ ℝ^{1 × n_hc}**: residual stream → 레이어 input (squeeze)
- **B_l ∈ ℝ^{n_hc × n_hc}**: residual stream 내부 변환
- **C_l ∈ ℝ^{n_hc × 1}**: 레이어 output → residual stream (expand)

업데이트:
```
X_{l+1} = B_l X_l + C_l F_l(A_l X_l)
```

(X_l ∈ ℝ^{n_hc × d}, F_l 은 ℝ^d → ℝ^d)

### 왜 좋아 보였나?
- residual width가 hidden dim 과 무관하게 조정 가능 → 추가 파라미터·연산 미미 (n_hc 는 d 보다 훨씬 작음)
- "**dynamic layer rearrangement**" — A,B,C 가 학습되며 레이어 순서·세기를 모델이 직접 조정 [P6]
- 실험: dense·sparse 모두에서 표준 residual 대비 우위 [P6]

### 그러나 — 깊은 stack 에서 실패

> "even though HC has demonstrated potential in improving model performance, we find that the training will frequently exhibit numerical instability when stacking multiple layers, which hinders the scaling of HC." — V4 paper [P1]

**원인**: B_l 의 **spectral norm** (||B_l||_2) 이 1을 초과하면, 깊은 stack 의 곱 `B_L · B_{L-1} · ... · B_1` 이 지수적으로 발산. 100+ layer 모델에서는 한 layer당 1.01배만 증폭돼도 100층이면 `1.01^100 ≈ 2.7` → 1000층이면 `~22000` 배 발산.

→ HC 는 매력적이지만 trillion-scale 에서는 불안정.

## 3단계: 수학적 도구 — Doubly Stochastic Matrix & Birkhoff Polytope

V4 의 해법을 이해하려면 두 가지 수학 개념을 알아야 한다.

### Doubly Stochastic Matrix

n×n 행렬 `M` 이 **doubly stochastic** 이려면:
1. 모든 원소 `M_{ij} ≥ 0`
2. 모든 행의 합이 1: `Σ_j M_{ij} = 1`
3. 모든 열의 합이 1: `Σ_i M_{ij} = 1`

전형 예: 단위 행렬, permutation matrix, uniform matrix `(1/n)·𝟙`.

### Birkhoff Polytope

모든 n×n doubly stochastic matrix 들의 집합 `M` 을 **Birkhoff polytope** 이라 부른다 (n×n 행렬 공간 안의 convex polytope).

**핵심 성질** (이게 mHC 의 결정타):
1. **Spectral norm 이 1로 bounded**: `||M||_2 ≤ 1` for all `M ∈ Birkhoff polytope`
2. **곱셈에 대해 closed**: `M_1, M_2 ∈ Birkhoff polytope` → `M_1 · M_2 ∈ Birkhoff polytope`
3. **Birkhoff 정리**: 모든 doubly stochastic matrix 는 permutation matrix 들의 convex combination [P7]

→ 1+2 가 합쳐지면: **깊은 stack 으로 곱해도 spectral norm 이 절대 1 을 넘지 않는다**. 정확히 HC 의 발산 문제를 막는 성질.

### Sinkhorn-Knopp Algorithm

임의의 양수 행렬을 doubly stochastic으로 **projection** 하는 iterative 방법 [P7, P8]:

```
M^(0) = exp(B̃)               # 양수 보장
loop t = 1 to T:
    M^(t) = T_r(T_c(M^(t-1)))   # 행 정규화 → 열 정규화
```

`T_r` 은 행 정규화 (각 행을 행합으로 나눔), `T_c` 는 열 정규화.

수렴 보장 (Sinkhorn 정리, [P7]): 양수 entry 행렬은 unique 한 doubly stochastic 형태로 수렴.

V4 는 **20회 iteration** (`t_max = 20`) 사용.

## 4단계: V4 의 해법 — mHC

이제 mHC 의 설계 의도가 명확해진다.

### 핵심 아이디어

**HC 의 B_l 매핑을 Birkhoff polytope 으로 강제 projection** 하면:
- HC 의 표현력 유지
- spectral norm ≤ 1 자동 보장
- 깊은 stack 의 발산 차단

### 수식 (V4 paper §2.2)

**raw 파라미터** (학습 가능):
```
Ã_l = α^pre_l · (X̂_l W^pre_l) + S^pre_l       # ∈ ℝ^{1×n_hc}
B̃_l = α^res_l · Mat(X̂_l W^res_l) + S^res_l     # ∈ ℝ^{n_hc×n_hc}
C̃_l = α^post_l · (X̂_l W^post_l)^T + S^post_l   # ∈ ℝ^{n_hc×1}
```

여기서 `X̂_l = RMSNorm(vec(X_l))`, `α` 들은 학습 가능 게이팅, `S` 들은 정적 bias.

**dynamic + static 분해**: 동적(input-dependent) 컴포넌트 `αW` 와 정적 컴포넌트 `S` 를 분리. 학습 초반에는 `α` 가 작아서 정적 부분이 지배 → 안정 시작.

### 제약 적용

```
A_l = σ(Ã_l)                       # Sigmoid → [0,1]
C_l = 2 σ(C̃_l)                     # 2·Sigmoid → [0,2]
B_l = SinkhornKnopp(exp(B̃_l), 20회)  # Birkhoff polytope projection
```

- A, C 는 Sigmoid 로 non-negative + bounded → **signal cancellation 방지**
- B 는 doubly stochastic projection → **spectral norm ≤ 1**

### 왜 dynamic + static 분해?

- 정적만: HC 효과 줄어듦 (input-aware 하지 않음)
- 동적만: 학습 초기 불안정
- 합치면: **초기에는 정적 dominant → 안정, 학습 진행되며 동적 활용**

## 5단계: 비용과 보상

### 비용

1. **추가 활성화 메모리**: residual stream 이 n_hc 배 두꺼움 (V4 는 n_hc=4)
2. **pipeline 통신 증가**: pipeline parallelism 에서 stage 간 전달 데이터 ↑
3. **Sinkhorn-Knopp 20회**: B_l 매번 계산 비용

### 완화

V4 는 §3.5.2 에서 mHC 비용을 적극적으로 억제:
- **Fused kernel**: A,B,C 계산을 단일 GPU kernel 로 융합
- **Recompute strategy**: 일부 중간 텐서를 backward 시 재계산 (메모리 ↓)
- **DualPipe 1F1B 스케줄 조정**: pipeline 통신 흡수

> "constrain the wall-time overhead of mHC to only 6.7% of the overlapped 1F1B pipeline stage"

→ 안정성·표현력 이득 대비 6.7% 오버헤드는 합리적.

## 6단계: 더 깊은 직관

### 왜 doubly stochastic 이 "맞는" 답인가?

**Permutation matrix 의 일반화**: doubly stochastic 행렬은 permutation matrix 들의 convex combination. permutation 은 정보 손실 없는 변환의 가장 단순한 예. 즉:

> "mHC 의 B_l 은 *soft permutation* — 정보를 재배치하되 잃지 않는다"

→ residual stream 의 n_hc 채널들 사이에서 정보를 **soft 하게 reroute**, 그러나 신호 세기 보존.

### Why 이전 시도들이 부족했나?

- **Spectral normalization** (Miyato et al. 2018): SVD 가 비싸 매 step 적용 불가
- **Weight clipping**: 표현력 크게 손상
- **LayerNorm 추가**: 부분적 효과, 근본 해결 아님
- **Birkhoff polytope projection**: closed form-ish (Sinkhorn-Knopp 이 빠름) + 곱셈 closed → 이상적

→ V4 의 "Sinkhorn-Knopp 으로 projection" 은 비용-효과 우수한 합리적 선택.

## 정리 — §2.2 한눈에 보기

| 단계 | 문제 | 해법 | 한계 |
|---|---|---|---|
| Standard residual | gradient vanishing ↔ representation collapse trade-off | `X + F(X)` | flexibility 부족 |
| **HC** [P6] | flexibility 확보 | residual stream `n_hc × d` 로 확장 | 깊은 stack에서 spectral norm > 1 → 발산 |
| **mHC** (V4) | HC 안정화 | B_l 을 Birkhoff polytope 으로 projection (Sinkhorn-Knopp) | 활성화 메모리·통신 비용 (6.7% 오버헤드로 억제) |

**핵심 통찰**:
1. residual 일반화는 학습 안정성과 표현력 동시 확보가 어려운 문제
2. **Doubly stochastic matrix 의 두 성질** (spectral norm ≤ 1, 곱셈 closed) 이 깊은 stack 안정성의 결정타
3. mHC = "**HC + 안정성 보장 manifold projection**" 의 우아한 결합
