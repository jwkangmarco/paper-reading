# §4.1 Data Construction — 차근차근

V4 의 base 학습 데이터를 어떻게 구축했는지에 대한 이야기. **32T+ 토큰** 의 양보다 **품질·다양성** 의 디테일이 중요.

---

## 1단계: 출발점 — V3 의 baseline 데이터 [P3]

V4 는 V3 의 데이터 수집 파이프라인을 **상속**:
- 웹 크롤링 + 코드 + 수학 + 논문 + 책 등 다양한 소스
- 14.8T 토큰 규모 (V3 base)
- 다국어 corpus

V4 의 출발점은 **"V3 데이터를 더 좋게, 더 길게, 더 다양하게"**.

---

## 2단계: 핵심 도전 — 4 가지 데이터 차원의 강화

V4 의 새 능력 (1M context, agentic, multilingual, scientific reasoning) 은 그에 맞는 데이터를 요구.

### (a) Web data — Model Collapse 방지

**문제**: 2024-2026 에 들어 웹 콘텐츠 자체에 LLM 생성물이 폭증
- LLM 으로 생성된 batched/templated 콘텐츠가 학습 데이터에 섞임
- Model Collapse [P44] 가설: 자기 출력에서 학습하면 quality 저하 누적

**V4 의 해법**:
> "we implement filtering strategies to remove batched auto-generated and templated content, thereby mitigating the risk of model collapse"

- 웹 데이터에서 **자동 생성·템플릿 콘텐츠 식별·제거**
- 인간이 만든 다양성 ↑ 데이터 우선
- 구체적 방법은 명시 안 됨 (LLM-as-judge 일 가능성 [P45])

### (b) Math & Code — Agentic 데이터로 강화

**기존 (V3)**: 정적 math/code corpus (서적, 논문, GitHub)

**V4 의 추가**:
- "Mid-training phase" 에 **agentic data** 통합
- → tool 호출, code execution trace, multi-step reasoning 등
- 단순 코드만이 아니라 **"코드를 어떻게 사용하는가"** 학습

→ 이는 §5 의 agent post-training 의 base 능력.

### (c) Multilingual — Long-tail 강화

**문제**: 영어 압도적, 중·일·한·기타 언어는 소규모

**V4 의 해법**:
- 다국어 corpus **확장**
- 특히 long-tail 지식 (각 문화권 고유 지식) 강화
- 평가 결과: MultiLoKo 38.7 → **51.1** (+12.4) [Table 1]

### (d) Long-Document — V4 의 차별화 포인트

**문제**: 1M context 능력은 **장문 학습 데이터** 없이는 못 만듦
- 일반 웹 데이터는 짧음 (수 KB ~ 수십 KB)
- 1M context 학습은 **수백 KB ~ MB 단위** 단일 문서 필요

**V4 의 해법**:
> "we place a particular emphasis on long-document data curation, prioritizing scientific papers, technical reports, and other materials that reflect unique academic values"

- **과학 논문·기술 보고서** 우선 수집
- 학술적 가치를 가진 long-document 우선
- → 단순 길이만 아니라 **품질 있는 장문**

→ 1M context 의 **품질** 이 데이터 단계에서 결정.

---

## 3단계: 결과 — 32T+ 토큰 corpus

```
V3-Base:  14.8T tokens
V4-Flash: 32T tokens   (+17T over V3)
V4-Pro:   33T tokens   (+18T over V3)
```

구성 카테고리:
- Mathematical contents
- Codes
- Web pages
- Long documents
- Other high-quality categories

→ 약 2× 의 토큰 규모. 단순 양 증가가 아닌 **품질 cleaning + 새 카테고리** 추가.

---

## 4단계: 전처리 (Tokenization) — 작은 변경

### V3 tokenizer 상속
- BPE (Byte-Pair Encoding) 기반
- 다국어 어휘
- 일부 special token

### V4 의 추가
- **Tool-call 관련 special token** 추가 (예: `<|DSML|>` — §5.1 참고)
- 어휘 크기는 **128K 유지**
- Token-splitting 전략과 Fill-in-the-Middle (FIM) 전략 V3 에서 그대로 [P3]

---

## 5단계: Sequence Packing — 데이터 활용 효율

### 일반 packing
- 학습 batch 효율 위해 여러 짧은 sample 을 한 sequence 로 concat
- 표준 GPT 학습의 기본

### V4 의 차이점

**(a) Source-aware packing** (Ding et al. 2024, [P46]):
- 같은 source 의 document 를 함께 packing → context coherence ↑
- truncation 최소화

**(b) Sample-level Attention Masking** (V3 에서 변경):
- V3: cross-sample attention 허용 (성능 약간 ↑)
- V4: **sample-level masking** — 한 sample 안에서만 attention
- 이유: long-context 학습에서 sample 간 cross-attention 이 noise → 해당 학습 정확도 ↓
- Trade-off: 약간의 성능 손해 vs long-context 학습 안정성

→ 1M context 학습에 **데이터 처리도 적응** 필요한 점.

## 6단계: 데이터 quality 의 정량적 효과 (§4.3)

V4 paper 의 base 모델 평가 (Table 1):

| 차원 | V3.2-Base | V4-Pro-Base | 개선 |
|---|---|---|---|
| World knowledge | 평균 ~70 | 평균 ~80 | **+10** |
| MultiLoKo (long-tail) | 38.7 | 51.1 | **+12.4** |
| FACTS Parametric (factual) | 27.1 | 62.6 | **+35.5** |
| LongBench-V2 | 40.2 | 51.5 | **+11.3** |

→ **데이터 강화의 효과가 가장 큰 영역**:
- World knowledge: web/multilingual cleaning 효과
- Long-tail: multilingual corpus 확장
- Factual: scientific paper 강화
- Long context: long-document curation

→ **§4.1 data construction 이 §4.3 evaluation 의 가장 큰 contributor**. 단순 토큰 늘리기가 아닌 **target 한 차원의 데이터 강화**.

## 정리 — §4.1 한눈에 보기

| 차원 | V3 | V4 변경 | 동기 |
|---|---|---|---|
| 총 토큰 수 | 14.8T | **32T (Flash) / 33T (Pro)** | scale up |
| Web data | 표준 | **Auto-generated 콘텐츠 필터** | model collapse 방지 |
| Math/Code | 정적 corpus | **+ agentic data (mid-train)** | agent post-training 의 base |
| Multilingual | baseline | **확장, long-tail 강화** | 다문화 long-tail 지식 |
| Long-document | 일반 책/문서 | **scientific paper 우선** | 1M context 품질 |
| Tokenizer | V3 그대로 | **+ tool-call special tokens** | post-training 의 tool 호출 지원 |
| Packing | document-level | **sample-level attention masking** | long-context 학습 안정성 |

**핵심 통찰**:
1. **데이터는 capability 의 base**. V4 의 1M context, agentic, multilingual 능력은 모두 데이터 단계 결정에 의존.
2. **품질 > 양**. 32T 토큰 자체보다 batched-content filtering, scientific paper 우선 같은 큐레이션이 더 중요.
3. **Model collapse 가 이제 실재 문제** [P44]. LLM-generated 콘텐츠 필터링이 standard 가 됨.
4. **Long-document curation** 이 V4 의 차별 포인트. 단순히 길게 packing 하는 것이 아닌 학술적 long-document 를 우선.
5. **Sample-level attention masking** 이 작아 보이지만 long-context 학습의 결정적 trade-off.
