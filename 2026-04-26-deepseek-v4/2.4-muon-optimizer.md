# §2.4 Muon Optimizer — 차근차근

§2 의 마지막 변화. attention·architecture 만큼 화려하진 않지만, **trillion-scale MoE 의 학습 효율을 좌우하는 핵심 결정**.

---

## 1단계: 출발점 — Adam / AdamW 의 지배

거의 모든 LLM 이 사용해온 표준 optimizer 는 **AdamW** (Loshchilov & Hutter 2017).

### 핵심 아이디어
- 각 파라미터마다 **element-wise adaptive learning rate**
- gradient 의 1차 momentum (`m_t`), 2차 momentum (`v_t`) 추적
- update: `θ_t = θ_{t-1} - η · m̂_t / (√v̂_t + ε)`
- W 는 weight decay 분리

### 장점
- 거의 모든 task 에서 **robust**
- hyperparameter 적게 튜닝해도 잘 됨
- Bf16/FP16 에서 안정

### 한계 (대규모 LLM 에서)
1. **Optimizer state 메모리 ×2** (m, v 둘 다 저장) → 1.6T 모델에서 수 TB
2. **느린 수렴**: 각 weight 를 element-wise 로만 봄 → matrix 의 구조 무시
3. **Trillion-scale 에서 sub-optimal**: matrix update 의 *방향*은 무시하고 *크기*만 조정

→ "matrix 다루는 방식이 더 똑똑해질 수 있다" 는 인식이 2024 년 본격화.

---

## 2단계: 핵심 통찰 — Update 방향의 직교화

수학적 직관:

> "두 개의 weight column 이 같은 방향으로 update 되면 redundant. **서로 직교하는 방향으로 update 하면 효과 ↑**"

### Orthogonalization 이란?

행렬 `M ∈ ℝ^{n×m}` 의 SVD: `M = U Σ V^T`.
- `U Σ V^T` 에서 **모든 singular value 를 1 로 만든** 결과: `M_⊥ = U V^T`
- 이게 "orthogonalized M"

### 만약 gradient 를 매 step 에서 orthogonalize 하면?
- **모든 방향에 동등한 update 강도** → degenerate direction 제거
- 표현력 손실 없이 weight 의 효과적 rank 유지
- **Adam 의 element-wise 적응** 보다 더 정교한 matrix-aware 방식

### 그러나 SVD 는 비싸다
- 매 step SVD = 학습 불가능한 비용
- → **근사 orthogonalization** 이 필요 → Newton-Schulz iteration 등장

---

## 3단계: Newton-Schulz Iteration

행렬을 **반복적 다항식 연산** 으로 orthogonalize 하는 방법.

### 기본 형태

```
M_0 = M / ||M||_F                         # Frobenius norm 으로 정규화 (singular values ≤ 1)
M_{k+1} = a · M_k + b · (M_k M_k^T) · M_k + c · (M_k M_k^T)^2 · M_k
```

- 계수 `(a, b, c)` 가 다항식 `f(x) = ax + bx³ + cx⁵` 를 정의
- 이 다항식이 `[0, 1]` 의 모든 singular value 를 1 근처로 끌어올림
- 반복하면 `M_k → U V^T` 로 수렴

### 왜 좋은가?
- **Bf16 에서 안정** — Newton-Schulz 는 단순 matmul 만 사용 [P14]
- GPU tensor core 에서 빠름 (matmul 은 가장 잘 최적화된 연산)
- SVD 대비 훨씬 저렴

---

## 4단계: Muon — Jordan (2024) 의 제안

[Keller Jordan 의 Muon 논문 (2024)](https://kellerjordan.github.io/posts/muon/) [P14]:

### Muon = MomentUm Orthogonalized by Newton-schulz

```
Algorithm Muon:
    G_t = ∇L(W_{t-1})                          # gradient
    M_t = μ M_{t-1} + G_t                       # momentum
    O_t = NewtonSchulz(μ M_t + G_t)              # Nesterov + 직교화
    W_t = W_{t-1} - η O_t                        # update
```

### 결과 [P14]
- NanoGPT speedrun: AdamW 대비 **35% 학습 속도 향상**
- 큰 scale 에서 **2× 효율** [P15]
- bf16 안정

### 한계
- **2D matrix 만 적용 가능** (vector/scalar param 은 AdamW 등으로 처리)
- 일반 Newton-Schulz 는 **계수 trade-off**:
  - 빠른 수렴용 계수: 정확도 떨어짐
  - 정확한 계수: 수렴 느림
- Q/K matrix 의 logit 폭주 → **QK-Clip** 같은 보조 트릭 필요

---

## 5단계: V4 의 Muon 구현 — 모듈별 분리

### Muon 사용
- attention QKVO matrices
- MLP / MoE expert weights
- **대다수 matrix parameters**

### AdamW 유지
- Embedding matrix (lookup table 성격, element-wise 가 더 적합)
- Prediction head (마지막 head, AdamW 의 stability 가 중요)
- mHC 의 static bias `S^pre/post/res`, gating factor `α`
- **모든 RMSNorm parameters** (작은 vector, AdamW 적합)

### 왜 분리?
- Muon 의 효율 이득은 **matrix update 의 구조** 에서 나옴
- vector/scalar param 은 그 이득이 없음 → AdamW 가 더 적절
- Embedding 은 sparse update 패턴이라 Muon 의 dense matrix 가정과 안 맞음

---

## 6단계: V4 의 Hybrid Newton-Schulz (10 step, 2 stage)

### 문제 — 단일 계수 세트의 한계

Newton-Schulz 다항식 `f(x) = ax + bx³ + cx⁵` 가 `[0,1]` 에서 1로 끌어오는 모양은 계수에 따라 다름:
- "**aggressive** 계수": 처음 빠르게 1 근처로 끌어오지만 1 근처 oscillate
- "**conservative** 계수": 부드럽게 수렴하지만 느림

→ 둘의 장점만 따자.

### V4 의 해법: 2-stage hybrid

**Stage 1 (첫 8 step) — aggressive**:
```
(a, b, c) = (3.4445, -4.7750, 2.0315)
```
- singular value 를 빠르게 **1 부근** 으로 끌어옴
- 이 계수는 [P14] 에서 제안된 표준값

**Stage 2 (마지막 2 step) — stabilization**:
```
(a, b, c) = (2, -1.5, 0.5)
```
- singular value 를 **정확히 1 로 안정화**
- Stage 1 의 oscillation 흡수

### 왜 10 step?
- 8+2 = 10 이 효율-정확도 sweet spot (V4 실험)
- 더 적으면 부정확, 더 많으면 비용 ↑

---

## 7단계: RMS Rescale Trick — AdamW LR 재사용

V4 의 Muon update 에는 추가 단계:

```
O_t = NewtonSchulz(μ M_t + G_t)
O_t = O_t · √max(n, m) · γ                     # RMS rescale
W_t = W_{t-1} (1 - η λ) - η O_t                 # weight decay + update
```

`γ = 0.18` 이 핵심.

### 왜 0.18?
- AdamW update 의 **RMS (root mean square)** 와 Muon update 의 RMS 를 매치
- 결과: AdamW 와 **동일한 learning rate scale** 사용 가능
- → AdamW 용 hyper-parameter 튜닝 결과를 그대로 Muon 에 reuse, 튜닝 비용 ↓

### 출처
- Liu et al. (2025) [P15] 에서 trillion-scale Muon 학습을 보여주며 도입한 트릭
- V4 가 동일하게 채택

---

## 8단계: QK-Clip 제거의 의미

일반 Muon 사용 시 **Q/K logit 폭주** 가 종종 발생:
- attention score `Q K^T / √d` 가 큰 값으로 증가
- softmax 에서 numerical 문제 발생

**일반 해법**: QK-Clip — Q, K 행렬의 norm 을 clip [P15]

**V4 의 차별**: §2.3.3 에서 query 와 KV entries 에 **RMSNorm 직접 적용** → logit 자체 폭주 차단
- → QK-Clip 불필요
- "**아키텍처 변경이 optimizer 변경의 부작용을 사전 차단**"
- §2.3 (Q/K RMSNorm) 과 §2.4 의 **시너지 설계**

---

## 9단계: ZeRO 와의 통합 (§3.5.1)

Muon 도입의 인프라 측 도전:
- ZeRO (Rajbhandari et al. 2020): 메모리 절감 위해 optimizer state 를 rank 별로 분산
- 표준 ZeRO 는 element-wise optimizer (AdamW) 가정
- Muon 은 **full gradient matrix** 가 필요해 conflict

V4 의 해법:
- **Dense param**: knapsack 알고리즘으로 분산, ZeRO size 상한
- **MoE param**: expert 별 독립 처리, padding 으로 균등 분배
- **자동 batching**: 같은 shape 의 consecutive param 을 묶어 Newton-Schulz 한 번에 처리
- **BF16 reduce-scatter**: gradient sync 통신량 절반

## 정리 — §2.4 한눈에 보기

| 항목 | AdamW | 일반 Muon [P14] | V4 의 Muon |
|---|---|---|---|
| Update 단위 | element-wise | matrix-wise (orthogonalize) | matrix-wise + 모듈 분리 |
| Optimizer state | 2× (m, v) | 1× (momentum) | 1× |
| Newton-Schulz | — | 5~6 step | **10 step (2 stage hybrid)** |
| Vector/scalar | — | 외부 처리 | AdamW 병용 |
| QK-Clip | 불필요 | 필요 | **불필요** (Q/K RMSNorm 으로 차단) |
| LR scale | 자체 | 별도 튜닝 | **AdamW 와 동일** (γ=0.18) |
| Trillion-scale 효율 | baseline | ~2× [P15] | 더 향상 |

**핵심 통찰**:
1. AdamW 는 element-wise 만 보지만 **LLM 의 weight 는 matrix 구조**가 본질 → matrix-aware optimizer 가 효율 ↑
2. Muon 의 직교화는 **degenerate direction 제거** → 같은 step 으로 더 많이 학습
3. V4 의 **2-stage Newton-Schulz** 는 빠른 수렴 + 정밀 안정화의 절충
4. AdamW 와의 **모듈 분리 + LR scale 매치** → tuning 비용 최소화하며 도입
5. §2.3 의 Q/K RMSNorm 과 시너지로 **QK-Clip 불필요** — 아키텍처 결정이 optimizer 의 부작용까지 흡수
