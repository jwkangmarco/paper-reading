# §5.1 Post-Training Pipeline — 차근차근

V4 의 가장 큰 methodological 변화. **mixed RL → On-Policy Distillation (OPD)** 로 post-training 의 핵심을 교체한 결정의 motivation 과 동작.

---

## 1단계: 출발점 — V3.2 의 mixed RL pipeline

### V3.2 의 post-training [P11]
- Specialist 별 SFT
- Mixed RL stage 에서 모든 domain 통합

```
Base model
   ↓ SFT (math, code, agent, writing 등)
   ↓ Mixed RL (모든 domain 동시 최적화)
   ↓ Final model
```

### Mixed RL 의 한계
- **Domain interference**: math 의 reward 와 writing 의 reward 가 서로 충돌
- **Reward hacking**: 모델이 일부 domain 의 평가 기준을 exploit
- **Scalability**: 새 domain 추가 시 전체 RL 재실행 필요

→ V4 가 이를 **specialist + OPD** 로 분리.

---

## 2단계: V4 의 새 pipeline — Two-Stage Paradigm

### V4 paper §5.1 의 핵심 변화

> "the mixed Reinforcement Learning (RL) stage was **entirely replaced by On-Policy Distillation (OPD)**"

```
Base model
   ↓
Stage 1: Specialist Training (각 domain 독립 학습)
   ├─ Math expert: SFT + GRPO
   ├─ Code expert: SFT + GRPO
   ├─ Agent expert: SFT + GRPO
   ├─ Writing expert: SFT + GRPO
   └─ ... (10+ specialists)
   ↓
Stage 2: On-Policy Distillation (unified model 통합)
   Student model ← multi-teacher OPD ← {Specialist E_1, E_2, ..., E_N}
```

---

## 3단계: §5.1.1 Specialist Training — 도메인 전문가 학습

### 단계
1. **SFT** — domain-specific 고품질 데이터로 fine-tuning, base capability
2. **RL with GRPO** — domain-aligned reward 로 특화 행동 추가 학습

### GRPO (Group Relative Policy Optimization)

**전 단계**: PPO (Proximal Policy Optimization)
- Actor + Critic + Reward + Reference Model = **4 LLM 동시 운용**
- 메모리 폭증

**GRPO** [P50]:
- **Critic 제거**, group 안에서 상대 평가
- 같은 prompt 에 대한 N 개 response 샘플
- Reward 의 평균을 baseline 으로, 각 response 의 advantage 계산:
  ```
  A_i = (r_i - mean(r_1, ..., r_N)) / std(r_1, ..., r_N)
  ```
- → 4 → 2 모델 (Critic 없음, 메모리 절감)

V4 의 GRPO 사용:
> "we implemented the Group Relative Policy Optimization (GRPO) algorithm, maintaining hyper-parameters closely aligned with our prior research"

→ DeepSeek-R1, V3.2 와 동일 파라미터.

### Reasoning Effort Modes

V4 가 specialist 마다 **3 가지 mode** 학습 (Table 2):

| Mode | 특징 | Use case |
|---|---|---|
| **Non-think** | 직관적·빠름 | 일상 질문, 응급 반응 |
| **Think High** | 의식적 분석, 느리고 정확 | 복잡 문제, 계획 |
| **Think Max** | reasoning 한계까지 push | 모델 최대 능력 탐색 |

각 mode 에 다른 length penalty + context window 적용.

### Generative Reward Model (GRM) — 핵심 혁신

**문제**: hard-to-verify task (writing quality, alignment 등) 는 rule-based reward 불가

**기존**: RLHF 위해 별도 scalar reward model 학습 (인간 annotation 다량 필요)

**V4 의 GRM** [P51]:
> "we apply RL optimization directly to the GRM itself. In this paradigm, the actor network natively functions as the GRM, enabling the joint optimization of the model's evaluative (judging) proficiency alongside its standard generative capabilities"

- **Actor 자신이 reward model 도 됨** (separate scalar RM 없음)
- Rubric-guided RL data 로 학습
- "**스스로 판단할 줄 아는 모델**"

**결과**:
- Robust scoring (모델이 자기 reasoning 으로 평가)
- 인간 annotation 최소
- Self-judging mechanism (Kimi K2 등도 유사 [P52])

### Tool-Call Schema — `<|DSML|>`

V4 가 새 tool-call format 도입 (Table 4):

```xml
<|DSML|tool_calls>
<|DSML|invoke name="$TOOL_NAME">
<|DSML|parameter name="$PARAM_NAME" string="true|false">$VALUE</|DSML|parameter>
</|DSML|invoke>
</|DSML|tool_calls>
```

**왜 XML?**:
- 기존 JSON-based tool call: escape 실패 등 errors
- XML: structured, escape 안전
- → **tool-call error 감소, 안정성 ↑**

### Interleaved Thinking

V3.2 → V4 의 변화 (Figure 7):
- **V3.2**: tool-result round 마다 reasoning trace 유지, **새 user message 시 모두 폐기**
- **V4**: tool-call mode 에서 **모든 round 의 reasoning 누적 유지**, 일반 chat 만 폐기
- 1M context 활용으로 **agent 의 일관된 long-horizon reasoning** 가능

### Quick Instruction — TTFT 단축

**문제**: chatbot 의 search trigger, intent recognition 등 sub-task 에 별도 작은 모델 사용 → redundant prefill

**V4 의 Quick Instruction**:
- Special token (`<|action|>`, `<|query|>`, `<|title|>` 등, Table 5) 으로 input 에 추가
- **이미 계산된 KV cache 재사용** → redundant prefill 제거
- → user-perceived TTFT (Time To First Token) 단축

## 4단계: §5.1.2 On-Policy Distillation (OPD) — 통합 단계

### Distillation 의 기본
- Teacher (강한 모델) 의 출력 분포를 Student (학습 대상) 가 모방
- Cross-entropy 또는 KL divergence loss 사용

### Off-policy vs On-policy

**Off-policy distillation** (전통적):
- Teacher 가 sample 생성 → student 가 학습
- 문제: **distribution shift** — student 가 자기 생성에서 못 보는 데이터 학습

**On-policy distillation** [P53]:
- **Student 가 자기 trajectory 생성**
- Teacher 가 student 의 trajectory 에 대해 token-by-token 지도
- 효과: train-test distribution mismatch 제거, 더 효율적

### V4 의 OPD Objective

```
L_OPD(θ) = Σ_{i=1}^{N} w_i · D_KL(π_θ || π_{E_i})
```

- `π_θ`: student (unified V4)
- `π_{E_i}`: specialist (math, code, agent, ...)
- `D_KL(π_θ || π_{E_i})`: **reverse KL** (mode-seeking)
- `w_i`: expert importance weight
- N > 10 (10+ specialist teachers)

### Reverse KL 을 쓰는 이유 [P53]

- **Forward KL** (`KL(P_teacher || P_student)`): teacher 의 분포를 student 가 *cover* 하도록 → mass-covering, 다양성 ↑
- **Reverse KL** (`KL(P_student || P_teacher)`): student 가 teacher 의 mode 에만 집중 → **mode-seeking**, low-quality 응답 회피

LLM 같이 quality > diversity 인 task 에서는 reverse KL 이 더 적합.

### Token-level KL vs Full-vocabulary KL

**기존 (효율적)**:
- Full vocab logit 비교는 비싸 → token-level KL 만 (각 token 위치에서 1 개 logit)
- RL framework reuse 가능 (advantage 자리에 KL 대입)
- 단점: **gradient variance 큼**, training instability

**V4 의 선택**:
> "we adopt full-vocabulary logit distillation in our OPD"
- 모든 vocab 의 logit 비교
- 더 안정적 gradient
- "faithful distillation of the teachers' knowledge"

→ infrastructure (§5.2) 에서 이걸 가능하게 만든 디자인이 핵심.

### Selective Learning

```
"the unified policy π_θ selectively learns from the specialized expert relevant to the current task context (e.g., aligning with the mathematics expert for math reasoning tasks and the coding expert for programming tasks)"
```

- Multi-teacher OPD 의 핵심: 모든 teacher 에서 무차별 학습 ❌
- → **task context 에 따라 적절한 expert** 에 align
- Trajectory 의 prompt 가 math 면 math expert, code 면 code expert
- Specialist 의 능력이 unified model 로 selective merge

## 5단계: 왜 OPD 가 mixed RL 보다 나은가?

| 항목 | Mixed RL | OPD |
|---|---|---|
| Domain interference | 있음 | **없음** (specialist 단계에서 분리 학습) |
| Reward hacking | 가능 | 적음 (teacher logit 모방) |
| 새 domain 추가 | 전체 재학습 | 새 specialist만 추가 |
| Reward signal 품질 | scalar (정보 적음) | full distribution |
| Training stability | hard | 안정적 (Off-policy 보다 [P53]) |
| 효율 | RL slow convergence | distillation 7-10× 빠름 [P53] |

### V4 의 결정 = "RL 의 본질적 어려움 회피"

> "the actor network natively functions as the GRM" — specialist 단계의 RL은 GRM 으로 해결
> "OPD has emerged as an effective post-training paradigm for efficiently transferring expert capabilities to a single, unified model"

→ 통합 단계는 RL 이 아닌 distillation 이 충분.

## 6단계: Pipeline 전체 흐름

```
┌─────────────────────────────────────────────────────┐
│              V4 Base Model (post-§4)                  │
└─────────────────────────────────────────────────────┘
                          ↓
            ┌─────────────┴─────────────┐
            ↓                            ↓
    [Domain 1: Math]          [Domain 2: Code]   ...
       SFT                       SFT                  
       GRPO + GRM                GRPO + GRM           
       3 modes                   3 modes              
            ↓                            ↓
    Specialist E_1            Specialist E_2     ...   (10+ specialists)
            ↓                            ↓
            └────────────┬───────────────┘
                         ↓
              Unified Student (initialized from base)
                         ↓
           On-Policy Distillation (multi-teacher)
              - Student rollouts trajectory
              - Each E_i 가 token-by-token 지도
              - Full-vocab reverse KL
              - Selective: task context 맞는 teacher
                         ↓
                   V4 (Final Model)
```

## 정리 — §5.1 한눈에 보기

| 단계 | V3.2 | V4 |
|---|---|---|
| Pipeline | base → SFT → mixed RL | base → **specialist (SFT+GRPO+GRM)** → **OPD** |
| Domain interference | exists | **avoided** |
| Reward signal | rule + scalar RM | **GRM (self-judging actor)** |
| RL algorithm | GRPO (mixed) | GRPO (per-specialist) |
| Final integration | mixed RL | **Multi-teacher OPD** |
| KL form | — | **full-vocab reverse KL** |
| Reasoning modes | 1 | **3 modes** (Non-think / High / Max) |
| Tool-call | JSON | **XML `<|DSML|>` schema** |
| Reasoning persistence | discarded each turn | **interleaved thinking** in tool-call |

**핵심 통찰**:
1. **Mixed RL 의 domain interference 가 V4 의 motivation** — specialist 분리로 회피
2. **OPD 가 RL 의 통합 단계 대체** — 더 안정, 더 효율, 더 다양한 expert 통합 가능
3. **GRM (self-judging actor)** 가 hard-to-verify task 에 대한 답
4. **Full-vocab reverse KL** 가 gradient stability 의 핵심 — infrastructure 가 이를 가능하게 함 (§5.2)
5. **3 reasoning modes** 와 **interleaved thinking** 으로 1M context 활용도 극대화
6. Pipeline 변화 자체가 V4 의 **methodology contribution**
